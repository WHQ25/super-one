两个 agent 在不同窗口里改同一个仓库,是两个互不知情的 agent。协作让这条边界变得可以跨越。

### 每次启动都要你批准

agent 请求启动一个协作者,你会看到它打算委派什么,然后批准或拒绝。启动任务渲染为 markdown 气泡而不是原始工具载荷,于是这个请求在你处理之前是可读的。子会话的启动会被引导向自治的权限模式 —— 一个需要你全程盯着的子会话,失去了意义。

### 是信箱,不是发完就忘

协作者之间通过信箱交换消息。消息在工具 UI 里以 markdown 渲染,信箱唤醒行会显示某个会话是被哪条消息叫醒的。回合进行中到达的通知会先排队,再经由会话自己的发送通道冲刷出去,于是一条消息永远不会落在一次写到一半的工具调用中间。

### 边界本身才是重点

协作者不必是同一个 harness。Claude 会话可以把任务交给 Codex 再把结果读回来,因为协作建立在共享的会话接缝上,而不是某一个引擎的 subagent 功能上。

### 它自带项目

如果协作者的工作目录从未被打开过,它会被注册为一个独立项目 —— 于是这些工作出现在你会去找的地方,而不是孤零零挂在父会话内部。
