Cursor 跑在自己的 SDK 上而不是 CLI 上,这恰好检验了 harness 接缝是不是真的"按引擎"设计的。

### 原生 SDK,完整接入

基于 SDK 1.0.27 完整接通 `@cursor/sdk`:会话、MCP、云端会话与恢复面全部映射到共享契约。这套集成放在自己的包里,与其他 harness 遵循同一模式。

### 自己的旋钮,共享的形状

权限模式与沙盒开关按照其他 harness 的同一方式暴露,于是无论用哪套引擎,聊天状态栏读起来都一样。完整的模型参数面可用,并带模型启用列表和按 harness 划分的偏好,于是 Cursor 的设置不会渗到别人那里。

### 不会堆成一面墙的设置

Cursor 的设置页拆成了分页,而不是一长条滚动。`Auto` 权限模式改名为 `Agent`,与它实际的行为一致。
