另外五套引擎是 SuperOne 与之对话的进程。DeepSeek 是 SuperOne 托管的运行时。

### 嵌入,而非外部进程

`@superone/deepseek` 把 dsh 运行时嵌入进程内,后端直接驱动它。凭据来自 SuperOne 自己的存储而不是另一个配置文件,于是你启用的引擎,由你启用它的这个应用来认证。

### 工具面,按会话挂载

每个会话挂载 dsh 的原生工具面,SuperOne 自身的 MCP 面桥接在旁,第三方 MCP 服务挂在作用域链上。MCP 配置的修改会应用到已经在跑的会话;服务器像其他每个 harness 一样从设置页管理。

### 委派与恢复

前台 subagent 跑在宿主面的工具表面上,被委派的子任务渲染为 Task 块,`subagent_fork` 工具负责这次分叉。fork 与冷恢复都做了 pin,于是会话会从停下的地方重新打开。会话会自动 compact,也响应 `/compact`。

### 一份读得懂的轨迹

轨迹账本渲染为一个基于增量折叠构建的面板,于是长时间运行仍然可滚动,而不是每来一个事件就重新推导一遍。失败的 subagent 会把 provider 诊断直接呈现在 Task 芯片上,而不是悄无声息地失败。

### 预设与安全

Agent 预设有了各自的图标和带动画的选择器,DeepSeek 的模式并入共享模型选择器,原生多模态图像输入也已接通。第三方 dsh 插件可以在运行时安装,自修改插件需要明确 opt-in,整套引擎被约束在沙盒支撑的权限预设之后。
