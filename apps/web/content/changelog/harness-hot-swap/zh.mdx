六个 harness 不可能都塞进安装包。所以一个都不塞。

### 零内置二进制

打包的平台二进制被移出应用。启用某个 harness 时,它的产物从 R2 镜像获取,npm 作为兜底;版本 pin 会预取进原子式的应用更新里,于是升级不会让你落到版本不匹配的状态。桌面端与 CLI 共用一个安装根目录和一条下载路径 —— 安装内核被提升到 runtime 层,两个宿主跑的是同一份代码。

### 每套引擎在设置里有了家

设置页新增 Harnesses 面板,每个 harness 的配置嵌套其中。选择器只列出你确实启用的,harness 顺序靠拖拽调整而不是一堆默认偏好下拉框,资源还有用户/项目两级作用域切换。

### 首次运行会先看一眼

引导流程会扫描你机器上已有的 CLI 并据此推荐 harness,而不是让你从六个可能没听过的名字里挑。当 pin 发生实质变化时,基于 epoch 的重新引导会再次触发流程,于是推荐不会过期。
