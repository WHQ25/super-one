## 它做什么

支持 ACP 意味着 SuperOne 接入的是一套协议,而不是一家厂商。任何会说 Agent Client Protocol 的 agent 都能作为一等 harness 运行;Grok 是第一个完整接通的。

## 哪些东西映射到共享契约

- 会话生命周期,于是 ACP 会话的创建、恢复与 fork 与其他引擎一样。
- 模型列表,按 agent 缓存,于是切换时不必每次都重新盘问 CLI。
- 斜杠命令,在你打开 `/` 弹窗时才懒加载,而不是启动时全量枚举。
- 权限模式与 worktree 工作目录,于是状态栏读起来和 Claude、Codex 一样。

## 它继承 SuperOne 的工具面

宿主会给每个 ACP 会话挂上 SuperOne 的 MCP 服务并注入宿主提示词。于是一个 ACP agent 在它自己的实现毫不知情的情况下,获得了浏览器、设备控制、Computer Use 与媒体工具。用户配置的 MCP 服务映射为 ACP 的 session servers,你加过的服务在这里同样生效。

## 为什么协议层才是对的接缝

接一家厂商,得到的是一个集成。接协议,意味着下一个兼容的 agent 是配置而不是代码 —— 这正是第五、第六套引擎只花了几天而不是几周的原因。

## 常见问题

**只能用 Grok 吗?** 不是。Grok 是已经接通并验证过的那个例子;接缝在协议本身。
