## 它做什么

WebMCP 让页面可以向正在浏览它的 agent 发布工具。内嵌浏览器负责发现它们,而在你信任该站点之后,agent 就能调用。

## 怎么工作

- **发现。** 浏览过程中从文档里读出页面工具。发现到的工具会呈现在界面上,于是在任何东西执行之前,你先看得到这个站点提供了什么。
- **按来源同意。** 调用页面工具需要对该来源做一次站点信任决定。授权会持久化,于是一个站点你批准一次,而不是每次访问都批准。
- **专门设计的聊天行。** 页面工具调用渲染成自己的一行,而不是通用的 MCP 输出,读起来就是它本来的样子。

## 为什么信任按站点而不按单次调用

能定义工具的页面,同样能给工具改名和重新定义。批准单次调用等于批准了一个名字,而这个名字背后的东西下次加载就可能变了。所以有意义的信任单位是来源。工具指纹覆盖剩下的情况:如果一个已批准的工具悄悄变成了另一个,这个变化会被抓住,而不是被继承。

## 为什么有用

因为 WebMCP 挂在内嵌浏览器上而不是某一个 harness 上,页面只发布一次工具,每套引擎都能调用。

## 常见问题

**站点能自己给自己授权吗?** 不能。发现是自动的,调用不是。在你信任该来源之前,什么都不会执行。
