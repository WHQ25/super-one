## 它做什么

协作者不必和启动它的会话跑同一套引擎。Claude 会话可以把任务交给 Codex,或者交给 Cursor、OpenCode、DeepSeek 以及某个 ACP agent,再把结果读回来。

## 它为什么成立

协作建立在共享的会话接缝上,而不是某一个引擎的 subagent 功能上。Claude 有 subagent,Codex 没有。如果协作是搭在 Claude 的 subagent 之上实现的,它就会变成一个别的引擎永远拿不到的 Claude 功能。在会话层实现,意味着被委派的单位是"一个会话" —— 而每套 harness 都能产出会话。

## 这带来什么

- 按长处委派:长推理交给一套引擎,小步快改交给另一套。
- 绕开能力缺口:移交给一个具备当前引擎所缺能力的 harness。
- 某套引擎撞上速率限制时继续推进,不必手动到别处重启任务。

## 常见问题

**结果拿回来的形式好用吗?** 好用 —— 协作者的产出经信箱以 markdown 抵达,而 handoff 带走的是一份持久的 Markdown 文档,不是一段口头总结。
