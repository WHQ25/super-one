## 它做什么

link 在两个已经存在的会话之间打开一个信箱。谁也不是谁的子会话;它们是两件正在进行的工作,现在可以互相触达。

## 怎么工作

- 挑一个已有会话建立连接。双方各自保留自己的历史、引擎与权限 —— 连接只是加了一条通道,不合并任何东西。
- 消息在工具 UI 里以 markdown 渲染,于是对面发来的消息读起来是文字,不是一坨 JSON。
- 唤醒行会显示某个会话是被哪条消息叫醒的,于是你能看清它闲置之后为什么又开始干活了。
- 在输入框里 `@` 提及某个具体协作者,可以点名跟其中一个说话。

## 什么时候用

- 两个会话在同一个接口的两侧工作 —— 一个做 API、一个做客户端 —— 需要就契约达成一致。
- 一个长时间运行的会话,在到达某个里程碑时应该通知另一个。
- 处在不同 worktree 里的会话,需要交换信息但不共享同一份 checkout。

## 常见问题

**它们能是不同引擎吗?** 可以。和其他协作模式一样,link 跨越 harness 边界。

**连接会合并它们的历史吗?** 不会。每个会话保留自己的记录;只有你通过信箱发送的消息会跨过去。
