## 它做什么

协作中的会话通过信箱交换消息,而不是往对方的对话记录里硬插。

## 怎么工作

- **消息以 markdown 渲染**在工具 UI 里,于是对面发来的内容读起来是文字,而不是一坨需要你解码的 JSON。
- **唤醒行**会显示某个会话是被哪条消息叫醒的。一个闲置的会话忽然又开始干活,是有据可查的。
- **回合中途到达的消息会排队。** 消息落到一个正处在回合中的会话时不会打断它,而是排队后经该会话自己的发送通道冲刷出去,于是它绝不会出现在一次写到一半的工具调用中间。

## 为什么排队很重要

把消息塞进一个正在运行的回合,意味着模型会在"工具调用"和"工具结果"之间看到它 —— 那是对话尚未处于自洽状态的位置。排队付出一点延迟,换来的是一份重放时始终讲得通的记录。

## 常见问题

**双方看到的是同一个信箱吗?** 是,它是一条共享通道。每个会话保留自己的记录;只有你发送的内容会跨过去。
