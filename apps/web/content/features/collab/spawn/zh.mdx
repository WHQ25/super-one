## 它做什么

spawn 启动一个子会话,并且你可以持续跟它对话。父会话仍然主导:它委派出一块工作,子会话完成,结果回到父会话的记录里。

## 怎么工作

- agent 请求派生一个协作者。你会看到启动任务渲染成 markdown 气泡 —— 是完整的任务说明,不是工具载荷 —— 然后批准或拒绝。
- 子会话以自治权限模式启动。一个需要你逐个工具批准的子会话,失去了委派的意义。
- 子会话出现在侧栏父会话之下,工作期间带一个待处理标记。
- 消息经由信箱回流。如果某条消息在父会话回合进行中到达,它会先排队,再经父会话自己的发送通道冲刷出去,而不是落在一次写到一半的工具调用里。

## 什么时候用

- 一块自成体系、你希望与主对话隔离的子任务 —— 迁移测试、批量重命名、起草数据迁移。
- 你想盯着看的工作。你可以继续跟子会话说话;它是一个会话,不是后台任务。

## 常见问题

**子会话必须用同一套引擎吗?** 不必。可以从 Claude 会话派生一个 Codex 子会话,反过来也行 —— 协作建立在共享的会话接缝上。

**它的工作落在哪里?** 如果子会话的工作目录从未被打开过,它会被注册为独立项目,于是这些工作出现在你会去找的地方。
