## 它做什么

可以给协作者一份自己的 git worktree,于是它的修改落在一个独立 checkout 里,而不是压在你的工作区之上。

## 为什么这对协作尤其重要

两个 agent 编辑同一份工作区,不是一个合并问题,而是一场竞态:一个写下某个文件时另一个正读到一半,两边都在一个从未存在过的状态上继续构建。worktree 给协作者一份自己的 checkout —— 同一个仓库和历史,磁盘上是分开的文件 —— 于是并行工作真的是并行,而不是交错。

## 怎么工作

- 协作者以该 worktree 作为工作目录运行。
- 本地未提交的改动可以选择带进这次 fork,用于任务依赖你还没提交的工作时。
- 它就是一个普通的 git worktree,于是你用已经在用的工具去查看、diff 和合并它。

## 常见问题

**必须用吗?** 不必。隔离是可选的 —— 一个只读或只出主意的协作者不需要它。
