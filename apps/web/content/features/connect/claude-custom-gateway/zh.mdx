## 它做什么

把 Claude 指向你自己跑的网关,或指向一个讲 Anthropic API 形状的第三方服务。

## 怎么工作

- base URL 与密钥按凭据配置,于是网关与你的直连 Anthropic 凭据并列存在,而不是取代它。
- 当某个 provider 讲的是不同的 wire 形状时,请求会经由一个代理 sidecar 做翻译。sidecar 的生命周期是应用的问题,不是你的问题 —— 包括确保它不会以孤儿进程的形式活得比应用还久。
- 模型分类复用本地目录,而不是从模型名字重新推导能力。一个网关服务的模型若目录已经认识,它拿到的就是这个模型的真实属性,而不是对这串字符串含义的启发式猜测。

## 最容易踩的那一个坑

跑 bash 工具的第三方网关可能会丢掉 `PATH`,如果环境是被替换而不是被合并的话。给 SDK 传 `env` 是**整体替换**环境的 —— 它不与父进程的合并 —— 于是一份只设了一个变量、忘了其余的网关配置,产出的是一个找不到 `git` 的 agent。加了网关之后 shell 命令突然报 command not found,就来这里看。

## 常见问题

**effort 选择还能用吗?** 映射 provider 不暴露它时,选择器是隐藏而不是显示成一个无效控件。这是有意的。
