## 它做什么

Cursor 通过原生的 `@cursor/sdk` 驱动,而不是一个命令行二进制 —— 这正是云端会话与恢复面能在 SuperOne 里可用的原因。

## SDK 而非 CLI

大多数 harness 是 SuperOne spawn 出来、通过 stdio 对话的进程。Cursor 是一次库调用。这个差别在聊天界面里是看不见的 —— 同一套会话契约、同一个状态栏、同样的工具行 —— 而它恰好检验了 harness 接缝到底是围绕"引擎"设计的,还是围绕"子进程"设计的。

## 你能得到什么

- **云端会话**,映射到共享的会话契约,于是它们像本地会话一样可列出、可恢复、可 fork。
- **恢复面**,于是被中断的会话有一条明确的回归路径,而不是就此丢失。
- **完整的模型参数**,带模型启用列表和按 harness 划分的偏好,不会渗到其他引擎那里。
- **权限模式与沙盒开关**,按其他每个 harness 的同一方式暴露。

## 常见问题

**需要装 Cursor 吗?** 这套集成用的是 SDK,没有另外的 CLI 需要安装 —— 启用该 harness 即可。

**`Agent` 就是原来的 `Auto` 吗?** 是。这个权限模式改名了,以匹配它实际的行为。
