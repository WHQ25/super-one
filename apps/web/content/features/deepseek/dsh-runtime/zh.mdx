## 它做什么

其他引擎是 SuperOne 与之对话的进程。DeepSeek 是 SuperOne 托管的运行时:dsh 运行时被嵌入进程内,后端直接驱动它。

## 这有什么不同

一个被 spawn 出来的 CLI 拥有自己的配置、凭据和工具注册表,宿主要跨进程边界与它协商。嵌入式运行时不需要这层协商 —— SuperOne 从自己的存储供给凭据、按会话挂载它的工具面,并且把配置变更应用到已经在跑的会话上,而不是等下次启动。

## 怎么工作

- **凭据来自应用本身。** 你启用的引擎,由你启用它的这个应用来认证,而不是另一个需要你保持同步的配置文件。
- **按会话挂载原生工具面。** 每个会话挂载 dsh 自己的工具,SuperOne 的 MCP 面桥接在旁,第三方 MCP 服务挂在作用域链上。
- **配置即时生效。** 修改某个 MCP 服务会应用到正在运行的会话;不必重启来让改动生效。
- **fork 与冷恢复。** 两者都做了 pin,于是会话从它停下的地方重新打开,而不是从"碰巧还在"的上一个检查点。

## 常见问题

**它还能用 SuperOne 的工具吗?** 能 —— 浏览器、设备、Computer Use 与媒体生成像对其他每个 harness 一样桥接进来。

**能装插件吗?** 能,而且是运行时安装。自修改插件需要明确 opt-in,整套引擎则运行在沙盒支撑的权限预设之下。
