## 它做什么

ACP 会话可以先计划再行动,而当它计划完毕,你拿到的是 Claude 计划模式用的同一套行内评论式评审界面。

## 怎么工作

- 计划模式从宿主界面进入,而不是只有 agent 才能决定的事。
- agent 的 `exit_plan_mode` 调用会打开评审面板 —— 你可以对计划的具体某一行留言、批准它,或把它退回去。
- ACP 自己的 `session/update` 计划条目映射到其他 harness 发出的同一套 todo 事件,于是一份在运行中演化的计划,会更新你本来就在看的那份任务清单。
- 权限请求映射到 SuperOne 的共享权限词汇,预批准的处理方式与别处一致。

## 为什么评审界面是共享的

评审一份计划,无论它由哪套引擎写出,都是同一个动作:你读它,你不同意其中一步,你就在那一步上说出来。给每个 harness 各配一套评审界面,只意味着毫无理由地把「表达不同意」这个手势学好几遍。计划经由不同的协议抵达;你拿它做什么并不改变。

## 常见问题

**每个 ACP agent 都支持计划模式吗?** 计划支持是按 agent 声明的;agent 报告支持时控件才出现。
