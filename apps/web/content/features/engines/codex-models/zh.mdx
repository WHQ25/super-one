## 它做什么

选择 Codex 会话跑在哪个模型上。列表来自你的账号,而不是烧进应用里的一张表。

## 怎么工作

- 模型从 Codex app-server 拉取并按 provider 缓存,于是列表反映的是你确实有权访问的模型,并随你的账号变化而更新。
- 选择是按会话的,与 effort 一起,在与其他每套引擎相同的那个选择器里。
- 用量与速率限制按模型跟踪,于是你看得出是哪一个在消耗你的额度。
- 推理支持是模型的属性,effort 控件只在模型确实支持时才出现。

## 自定义 provider

Codex 可以通过它自己的 `model_providers` 配置指向自定义 provider,包括那些讲 Chat Completions 形状而非 Responses 的端点。provider 注册表负责这层翻译,于是你已经在跑的网关不必改动就能服务一个 Codex 会话。

## 常见问题

**换模型会重置线程吗?** 不会。模型从下一轮开始生效,线程继续。
