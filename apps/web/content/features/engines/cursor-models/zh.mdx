## 它做什么

Cursor Agent 跑在 Cursor 自己的 SDK 上,而这套 SDK 暴露的模型参数被完整呈现,而不是收缩成一个下拉框。

## 怎么工作

- 模型列表从你的 Cursor 账号读取,于是它跟随 Cursor 实际提供给你的东西,而不是烧进某个版本里的一张表。
- 每个参数都以数据形式声明在 harness 上,而不是在调用点分支,这就是为什么这里的选择器与 Claude 或 Codex 上看起来一致。
- 一份启用列表决定某个 harness 被允许发送哪些参数,于是一个 Cursor 支持而另一套引擎不支持的旋钮,在那套引擎上直接不渲染。
- 选择是按会话的,并在重启后保留,与权限模式和工作目录一起。

## 为什么是列表而不是表

SuperOne 里每套引擎的目录都从账号读,而不是从应用读。这才使得厂商周二上线的模型不必等应用更新就出现在选择器里;这也是为什么选择器偶尔会显示一个你并未启用的模型 —— 目录是厂商的答案,不是我们的。

## 常见问题

**Cursor Agent 需要装 Cursor 编辑器吗?** 不需要。它直接对接 SDK,编辑器不在链路上。
