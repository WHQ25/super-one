## 它做什么

DeepSeek Agent 的「模式」就是 agent 预设:每一个都是一份组合,决定模型拿到哪些工具、它的提示词说什么。与之并列的是运行时插件安装,以及一组由沙盒支撑的权限预设。

## Agent 预设

一个预设是一个目录,里面放着一份 `agent.cordis.yml` —— 一份 agent 平面的组合。名册在每个进程内把每个预设挂载一次,置于一个常驻 scope 下;会话通过把自己的 agent scope 挂到那个挂载点之下来加入。预设自带图标,于是在某个预设下启动的会话,不必翻设置就能在侧边栏里认出来。

组合是 YAML 的事,不是 SuperOne 的事。应用只拥有那道接缝:它驱动的那一小片名册,以及界面读取的那份投影。

## 插件

插件在运行时装进 dsh 树,这才使得一个预设能引用应用并未内置的工具。因为运行时是进程内嵌入而非外部进程,装好的插件对下一个会话立即可用,不需要重启任何东西。

## 权限预设

dsh 的权限词汇把它真正强制执行的两个旋钮捆在一起 —— shell 与文件系统所处的沙盒模式,以及是否会提出审批问题:

- **Read-only** —— 任何地方都不写;读与搜索自由运行。
- **Workspace write** —— 只写本项目与临时目录,且每次写之前询问。
- **Danger full access** —— 无沙盒,不询问。

dsh 默认自带后两个。read-only 是补上的,因为 SuperOne 在其他每个 harness 上都提供「只看不动」模式,而 dsh 的沙盒词汇里本来就有这个模式 —— 缺的只是那一行预设。

## 常见问题

**这跟 Claude 的权限模式是一回事吗?** 它们为展示而映射到共享词汇上,但上面这些名字是 dsh 实际强制执行的机制。
