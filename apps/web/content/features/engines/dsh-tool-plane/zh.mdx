## 它做什么

DeepSeek Agent 按会话挂载它自己的文件、搜索、shell 与 todo 工具,SuperOne 的 MCP 面桥接在旁,而不是取而代之。

## 怎么工作

- 原生工具跑在沙盒 provider 之下:文件系统与 bash 执行器都在沙盒里,shell 环境是组合出来的,而不是整体继承。
- SuperOne 自己的工具 —— 浏览器、生图生视频、widget、小程序、设置 —— **原生**注册在 agent scope 上,于是它们以普通 dsh 工具行的形式出现,而不是从另一条传输通道抵达。
- 有副作用的调用会驻留并抛出权限请求,携带工具名、解析后的参数与调用 id。批准会释放这次驻留的调用;其他任何结果都以模型可读、可据以行动的理由拒绝。
- 请求还携带发起调用的那个 dsh 会话。对被委派的子 agent 而言那是子会话自己,而回答提示的是拥有其血缘的那个 SuperOne 会话 —— 于是嵌套 agent 的批准仍然出现在你面前。

## 为什么是「桥接在旁」

另一条路 —— 把 dsh 的工具经由 SuperOne 的 MCP 服务代理出去 —— 会让每次原生调用都走一趟它本不需要的往返,还会让两族工具渲染得不一样。注册到 agent scope 意味着:一个工具面、一条权限路径、一种行样式。

## 常见问题

**可以不带 SuperOne 工具跑吗?** 可以。不传它们,会话就只带 dsh 的文件与 shell 工具运行。
