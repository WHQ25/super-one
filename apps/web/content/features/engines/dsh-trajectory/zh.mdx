## 它做什么

一个可折叠面板,展示 DeepSeek 会话实际做了什么 —— 轮次、请求、步骤、工具调用与其结果 —— 并且在数千条事件之后仍然可读。

## 增量折叠

面板建立在一次「折叠」之上:对会话日志的一次前向遍历,并保持打开,于是一个进行中的会话可以逐事件折叠,而不必每次从头来过。

dsh 的日志 seq 连续,其正常顺序本身就是因果的(`turn/start` → `request/header` → `step/start` → chunk → `assistant/message` → `tool/call` → `tool/result` → `step/end` → `turn/end`),于是这次遍历只需一点「开括号」状态就能保持线性。没有任何东西是从挂钟顺序推断出来的 —— 每一次关联都来自显式 id 或一个开着的括号。

把那份状态保持打开,正是这个面板负担得起的原因。流式的一轮会持续追加事件,而每次轮询都重折整份日志,代价就是每次都付一遍完整历史。折叠改为只消费新增的部分,并报告这些新增改变了什么 —— **包括它修订过的记录**,因为一条 `tool/result` 完成的是数千条事件之前开启的那次调用。

## 为什么不直接渲染日志

原始 dsh 日志是一份正确却不可读的记录:单单一轮就可能有数百条事件,其中大多数是 chunk。折叠把它投影成你真正据以思考的单位 —— 一次调用与它的结果,一个步骤与它产出了什么 —— 并让这个投影足够便宜,可以实时更新。

## 常见问题

**对我没在看的会话有开销吗?** 折叠随日志推进;面板读的是投影。
