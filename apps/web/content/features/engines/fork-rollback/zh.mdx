## 它做什么

Codex 自己的协议支持 fork 一份 thread 和把它回退若干轮,SuperOne 直接驱动这两个操作,而不是模拟它们。

## 是原生的,不是模拟的

把一份截短的对话记录重放进一个新线程来实现"回退",只是一种近似:服务端状态与客户端对它的认知会漂移。Codex 在协议层暴露了这个操作,可以在某个 turn id 上截断,于是回退是这条线程真的动了,而不是一份看起来像它的副本。

## 怎么工作

- **Fork** 在选定的某一轮复制线程并在新会话里继续,原线程保持完整。
- **Rollback** 让线程本身退回 N 轮,并从那里继续。
- 两者都 pin 到某个协议版本 —— 这个操作的形态在 Codex 各版本间变过,版本不匹配的失败方式看起来像数据丢失,而不像版本问题。

## 常见问题

**什么时候用 rollback 而不是 fork?** 后面的回合就是错的、你想让它们消失时用 rollback。它们可能是对的、而你想并行试第二条路时用 fork。
