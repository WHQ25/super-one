## 它做什么

挂上需要走一趟 OAuth 浏览器往返的 MCP 服务,而不必离开应用去完成它。

## 怎么工作

- 授权页在 SuperOne 的内嵌浏览器里打开,而不是系统浏览器,于是重定向回到的是应用自己拥有的窗口。
- token 在重定向处被捕获,写进 SuperOne 的凭据存储,与你的 provider 密钥放在一起。
- 之后这个服务像任何其他 MCP 服务一样挂到 OpenCode 会话上;从模型那一侧看,它没有任何特别之处。

## 为什么值得做

带 OAuth 的 MCP 服务在桌面 agent 里通常很别扭:流程要浏览器,浏览器要重定向目标,而重定向目标必须是能把 token 交回来的东西。拥有浏览器就闭合了这个环。这正是 agent 自己驱动的那个内嵌浏览器 —— 这项能力本就因为别的理由存在,OAuth 流程是白捡的。

## 常见问题

**token 会与其他 harness 共享吗?** 凭据存储是共享的,于是你授权过一次的服务,在任何挂载它的地方都可用。

**服务的 token 过期了怎么办?** 重跑一次挂载流程会重新打开授权并替换掉已存的 token。
