## 它做什么

每套引擎都从磁盘读一份项目说明文件,而 SuperOne 把这份文件当作项目的大脑,而不是某一个 harness 的私有配置。

## 各引擎看哪里

- **Claude** 读 `CLAUDE.md`,把用户级文件与项目文件合并,并在你进入某个目录工作时,叠加加载该目录下的文件。
- **Codex** 读 `AGENTS.md`。
- **OpenCode** 通过 `/init` 写自己的那份。
- 其余各家遵循自己的约定,SuperOne 把它们呈现出来,而不是覆盖掉。

## 为什么按目录分文件很重要

一个 monorepo 的根说明与它的 `apps/desktop` 说明回答的是不同问题 —— 一个是「这个仓库怎么摆的」,另一个是「在这个子系统里什么会咬你」。让根文件保持精简、让子系统文件承载细节,才使得两份都值得读;单独一份两千行的文件,人会跳着看,模型会被稀释。

## Memory

与说明文件并列,agent 还可以保有一份持久 memory:关于你的事实、你给过的指导、进行中的项目约束、指向外部资源的指针。memory 装的是仓库尚未记录的东西 —— 代码结构与 git 历史更适合去读,而不是去记。

## 常见问题

**各引擎会看到彼此的文件吗?** 不会。各读各的约定;SuperOne 不做交叉投喂。
