## 它做什么

小程序在 SuperOne 内部、由 agent 通过四个 MCP 工具开发 —— 开发中的应用是实时注册的,于是你是编辑加重载,而不是打包加安装。

## 四个工具

- **`miniapp_dev_setup`** —— 脚手架一个新应用。`vanilla` 给你单个 `index.html`,不需要构建;`react` 给 React + TypeScript + Tailwind,需要构建。作用域是 `project`(只在该项目里可见,且 `.s1-dev.json` 可提交)或 `user`(本机处处可见)。
- **`miniapp_dev_register`** —— 把应用指向已经存在的源码。它从目录根或 `dist/` 读 `manifest.json`,可以顺手装一个 dev 指针,也可以只注册。
- **`miniapp_dev_pack`** —— 准备分发时产出 `.s1app`。
- **`miniapp_dev_update_types`** —— 刷新既有应用里的 `superone.d.ts`,让宿主 API 的类型与你正在跑的版本对上。

## 双运行时的形状

一个小程序不是一个程序。受信任的 **Node 宿主**掌管计算与 agent 工具;**WebView** 掌管渲染。一个两边都要用到的功能 —— 而大多数功能都是 —— 必须两侧都接通,而反复出现的错误是接了一侧、测了另一侧。当某个东西在开发时能用、装好之后却静默地什么都不做,先来这里看。

## 为什么在应用内开发

被构建出来的这个应用,本身就是一组 agent 可以调用的工具。在别处开发意味着 agent 在一整个安装周期走完之前,用不上它刚写好的东西。实时注册把这个循环压平了:写、重载、调用它。

## 常见问题

**项目作用域的 dev 应用会被提交吗?** `.s1-dev.json` 按设计就是可提交的,于是打开这个项目的同事拿到的是同一个应用。
