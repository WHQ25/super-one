## 它做什么

从市场安装 plugin,或把应用指向你自己的市场 —— 一个 plugin 把 skill、subagent、hook、命令与 MCP 服务打成一个可安装的单元。

## 怎么工作

- 市场就是应用从中读取清单的一个仓库;你可以在公开市场之外,加上你们团队自己的。
- 安装一个 plugin 会一次性注册它携带的全部内容:它的 skill 出现在 `/` 选择器里,它的 subagent 出现在专职者名册里,它的 MCP 服务出现在挂载列表里。
- plugin 提供的 skill 带 `plugin:skill` 命名空间,于是两个市场可以各自发一个 `deploy` 而不互相遮蔽。
- plugin 按用户或按项目安装,取决于装在哪里 —— 这才使得一个项目能钉住它期望贡献者拥有的那套工具链。

## 为什么要打包而不是各自分发文件

一套 agent 工作流的各个零件并不独立:一个调用 MCP 服务的 skill,没有那个服务就没用;一个给 subagent 工具门控的 hook,没有那个 subagent 就没有意义。分开分发意味着每个使用者都要手工重新组装同一套东西,而其中总有一个会装错。打包出来的才是真正能跑的那个单元。

## 常见问题

**我能做一个但不发布吗?** 可以 —— 本地目录就能作为市场来源。
