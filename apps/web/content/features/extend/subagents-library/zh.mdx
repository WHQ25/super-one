## 它做什么

定义专职 subagent —— 各自带自己的提示词、工具白名单与模型 —— 并从主会话把活派给它们。

## 怎么工作

- 一个 subagent 是一份 Markdown 文件,frontmatter 声明它的名字、描述、模型与工具。父 agent 挑选哪个专职者适合某项任务时,读的就是这句描述。
- 运行中的 subagent 渲染为嵌套 Task 块:子 agent 的步骤出现在发起它的那次调用之下,按 `parentToolUseId` 递归重建,于是嵌套好几层的树仍然读起来像一棵树。
- 工具访问用 `PreToolUse` hook 门控,而不是只信 frontmatter —— 白名单在调用时被强制执行。
- subagent 不继承主会话追加的系统提示词。它的提示词是它自己的,这正是重点:一个继承了「赶紧发」的评审者,就不是评审者了。

## 什么时候值得

当答案需要横跨很多文件去读、而你只想要结论不想要文件转储时,而且几件事确实彼此独立时,才做扇出。一次在你已经定位到的文件里的查找,自己直接做比派出去更快。

## 常见问题

**subagent 能再派生自己的 subagent 吗?** 支持嵌套,并递归渲染。
