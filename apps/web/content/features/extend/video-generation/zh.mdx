## 它做什么

Sora、Veo、Seedance 与 Ark 归入同一张协议表之后,`media_generate_video` 无论由哪一家来应答,看起来都一样。

## 怎么工作

- 每个 provider 的提交 / 轮询 / 取回形状都以数据形式声明在表里,而不是在调用点分支 —— 加一个 provider 是加一行,不是加一条代码路径。
- 视频生成耗时且异步,于是任务返回一个句柄,由 `media_video_status` 汇报进展。会话不会阻塞着等一次渲染。
- **花钱的任务执行前需要明确确认。** agent 不能替你决定「再渲染一次是值得的」。

## 为什么这个确认不是可选的

在这个工具面上,视频生成是唯一一个重试循环真的带着账单的工具。其他工具的失败代价是浪费时间,这一个的代价是浪费钱,而一个不确定的模型天然会再试一次。确认正是「再试一次」不再免费的那个位置,而这才让不确定性不至于滚雪球。

## 常见问题

**确认之前能看到费用吗?** 确认里会写明所用的 provider 与模型,而价格正是挂在这上面的。

**渲染途中关掉应用会怎样?** 任务是 provider 那边的;句柄是重新连回去的凭据。
