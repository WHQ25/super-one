## 它做什么

浅色、暗色,或跟随系统。两种模式是两套独立设计,而不是同一套设计把明度反过来。

## 浅色模式是造出来的,不是推导出来的

浅色模式在 token 层按反转 chrome 构建:在暗色下最深的表面,在这里变成最浅的;层级是重建的,不是继承的。每一条 token 通道都被显式写入,于是没有哪个值会悄悄回落到暗色默认值。

落在品牌填充色上的文字颜色,是由该填充色按对比度算出来的,而不是挑一次定终身。因为品牌色相由用户自由调节,手工挑的前景色在大部分取值下都会是错的 —— 而在极高亮度下,填充色物理上承载不了多少颜色,推导过程把这一点考虑了进去,而不是产出一个读不清的色块。

## 跟随系统

系统模式跟随操作系统外观。当原生 vibrancy 生效时,应用会显式钉住自己的外观 —— 否则一个 vibrant 窗口会独立于应用主题去跟随系统,两者可能对不上。

## 常见问题

**mock 和预览会跟随主题吗?** 会 —— 内嵌的产品界面派生自同一套 token,所以它们和应用其余部分一起切换。
