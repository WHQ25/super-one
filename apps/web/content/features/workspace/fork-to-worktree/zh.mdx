## 它做什么

在任意历史消息处分叉会话,并把副本落到一个全新的 git worktree 里,于是"对话的分支"和"代码的分支"是一起创建的。

## 为什么这两件事该在一起

分叉会话去试另一种做法,通常意味着代码也即将分岔。在同一份 checkout 里做,意味着无论对话分得多干净,两次尝试在磁盘上还是互相覆盖。把创建 worktree 作为 fork 的一部分,让隔离成为默认,而不是一个你事后才想起来的步骤。

## 怎么工作

- 选好分叉点,新会话就以一个全新 worktree 作为工作目录打开。
- 是否把本地未提交的改动带进这次分叉是可选的 —— 任务依赖你还没提交的工作就带上,想要一个干净分支就不带。
- 结果是一个普通的 git worktree,会出现在 `git worktree list` 里,合并方式和别的没有区别。

## 常见问题

**原会话会怎样?** 什么都不会。它保留自己的会话和自己的 checkout。
