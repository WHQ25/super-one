## 它做什么

fork 在任意一条历史消息处复制会话并在新会话里继续,原会话保持不动。

## 为什么用 fork 而不是 rewind

rewind 把会话退回去,并丢弃之后的内容。fork 两边都留:原会话保持原样,副本从你选的那一点继续。后面的回合确实错了就用 rewind;它们可能是对的、而你想并行试点别的,就用 fork。

## 怎么工作

- 挑任意一条历史消息作为分叉点,在它之前的一切都会被带过去。
- 分叉出来的是一个完整的本地会话 —— 有自己的标题、自己的状态、在侧栏里自己的位置。
- 从那一点起两个会话彼此独立运行,你想的话也可以让它们跑在不同引擎上,比较两套引擎面对同一份起点会怎么做。

## 常见问题

**每套引擎都支持 fork 吗?** 这项能力按 harness 而不同,应用把它声明为数据而不是假定 —— Claude 通过 SDK fork,Codex 通过在某个 turn id 上做 thread fork,其余引擎则用它们各自的等价方式(如果有)。
