# Antigravity (ACP) runtime contracts

Non-obvious upstream behaviors that SuperOne depends on.

## 1. Sibling `localharness_external` binary requirement (observed in 1.3.0)

- **Behavior**: `agy_acp_server.par` (`agy_acp_server.exe` on Windows) spawns a sibling `localharness_external` (`localharness_external.exe` on Windows) executable from the same directory.
- **SuperOne code**: `packages/runtime/src/harness/antigravity-runtime.ts`, `packages/runtime/src/harness/antigravity-zip.ts`
- **Guard**: `packages/runtime/src/harness/antigravity-runtime.test.ts`

## 2. Plaintext OAuth prompt lines on stdout (observed in 1.3.0)

- **Behavior**: During Google OAuth (`oauth-personal` / `oauth-business`), `agy_acp_server.par` may write human-readable OAuth instructions and the `https://accounts.google.com/...` URL directly to `stdout`, which is otherwise the NDJSON ACP transport stream.

## 3. Native `~/.gemini` & OS Keyring reuse, per-process `TMPDIR`, and ambient env stripping (observed in 1.3.0 / 1.5.3)

- **Behavior**:
  1. `agy` `1.5.3` (`acpLanguageServer`) natively reads user customizations, MCP servers, skills, rules, brain transcripts, and conversation SQLite databases from `~/.gemini` (`~/.gemini/antigravity-cli/...`) and stores OAuth tokens in the OS Keyring (`keyringAuth` / `jetski-standalone-oauth-token`), ignoring `GEMINI_HOME` and `AGY_ACP_FORCE_FILE_STORAGE`.
  2. SuperOne does **not** override `--gemini-dir` or `GEMINI_HOME`, so Antigravity ACP sessions reuse the user's native `~/.gemini` configuration and existing CLI Keyring login directly. Because Keyring-backed OAuth leaves no `oauth_creds.json` file on disk, `AntigravityAuthService` and `authenticateAntigravityRuntime` persist `oauthSignedIn` in `~/.superone/antigravity/auth-config.json` and abort session startup immediately (`ANTIGRAVITY_AUTH_REQUIRED`) if `authenticate` emits an interactive OAuth URL prompt on `stdout` or `stderr`.
  3. Each spawned process still receives an isolated `TMPDIR` under `~/.superone/antigravity/tmp` and strips ambient `GEMINI_*` / `GOOGLE_*` / `CLOUD_SHELL` variables from `baseEnv` so unrelated shell credentials cannot override the configured authentication method.
- **SuperOne code**: `apps/desktop/src/main/acp/antigravity-profile.ts`, `apps/desktop/src/main/acp/antigravity-oauth-url.ts`, `apps/desktop/src/main/acp/antigravity-auth-service.ts`, `apps/desktop/src/main/acp/antigravity-runtime-bridge.ts`, `apps/desktop/src/main/acp/antigravity-db-usage.ts`
- **Guard**: `apps/desktop/src/main/acp/antigravity-auth-service.test.ts`

## 5. Per-turn real-time token usage and SQLite `steps` schema evolution (observed in 1.4.5 / 1.4.8 / 1.5.3)

- **Behavior**:
  1. Conversation `.db` files use either `steps(idx INTEGER PRIMARY KEY, step_type, metadata, step_payload, ...)` (`1.4.8+`), `steps(idx INTEGER PRIMARY KEY, step_payload BLOB)` (`1.4.5`), or `steps(step_index, step_type, step_payload, metadata)` (`1.3.0`). Only `step_type = 15` (`STEP_TYPE_PLANNER_RESPONSE`) represents conversation planner steps; `step_type = 23` is an internal context-compaction checkpoint call (~250k tokens) and must be excluded from turn usage.
  2. During a turn, `localharness_external` emits `StepUpdate` followed by `UsageUpdate`. At turn end, `agy acp` returns `PromptResponse(stop_reason, usage=turn_usage)`.
  3. On the ACP wire, `PromptUsage.input_tokens` sums full prompt tokens across all LLM calls in the turn (including uncached re-uploads and subagent steps), and in `1.5.3+` `PromptUsage.output_tokens` already includes `thought_tokens` (`total_tokens == input_tokens + output_tokens`). In SQLite `StepMetadata.ModelUsageStats` (protobuf field 9), each planner step $k$ has total prompt occupancy `stepPrompt(k) = input_tokens + cache_read_tokens` and total output `stepOut(k) = max(output_tokens, candidates_tokens + thoughts_tokens)`. Because Gemini implicit caching aligns to 4,096-token blocks, takes multiple steps to warm up (`cache_read_tokens = 0`), and expires after 5 minutes of idle time, summing raw `input_tokens` across steps re-counts uncached prompt prefixes. Instead, incremental input added to the context window on step $k$ is `max(0, stepPrompt(k) - max(prevContext, cache_read_tokens(k)))`, seeded with `prevContext` from the last planner step before the current turn's `USER_INPUT` boundary (and resetting `prevContext` if `stepPrompt(k) < prevPrompt` after context compaction). When SQLite turn usage is available, `syncAntigravityTurnFromDb` uses the SQLite incremental turn summary directly rather than taking `Math.max` against cumulative `PromptResponse.usage`.
  4. Thinking steps are opened lazily upon receipt of actual non-empty `agent_thought_chunk` updates (never eagerly on prompt dispatch or tool-advance), and empty thinking frames are retracted so the UI never displays phantom "reasoning..." states.
  5. `agy` `1.5.3` does not emit an ACP compaction lifecycle (`compaction_update` / `auto_compact_*` / `x.ai/compact_conversation`). `step_type = 23` is one finished checkpoint, not a start: `created_at` and `completed_at` on that row are the duration, the previous planner step's occupancy is the pre-token count, and the next planner step's prompt is the post-token count. SuperOne sends `/compact` as a normal `session/prompt` (that turn is the manual start and end) and reads the conversation db once per new `tool_call`, plus once when the turn settles, to emit an automatic end only.

- **Guard**: `apps/desktop/src/main/acp/antigravity-slash-and-usage.test.ts`, `apps/desktop/src/main/acp/antigravity-compaction.test.ts`, `apps/desktop/src/main/acp/antigravity-subagent.test.ts`, `apps/desktop/src/main/session/backends/acp-backend.test.ts`, `apps/desktop/src/main/usage-stats-service.test.ts`

## 7. MCP, `run_command`, and `edit_file` tool `step.content` timestamp header, `.system_generated/steps/<N>/output.txt` spill files, and full input/output/diff preservation (observed in 1.4.5 / 1.5.3 / 1.23.2)

- **Behavior**:
  1. `localharness_external` and `acpLanguageServer` prepend `Created At: <ISO>\nCompleted At: <ISO>\n` to `step.content` (which `AgyAdapter._stream_live_step` / `ACPServer.sendStepUpdatesWithMode` emits as `rawOutput` and `content[0].content.text` on `tool_call_update(status="completed")`).
  2. When an MCP or built-in tool output (including `run_command`) exceeds the step inline limit (~10 KB), Antigravity writes the full body to `file:///.../.system_generated/steps/<N>/output.txt` and replaces `step.content` with either `The output was large and was saved to: file:///.../.system_generated/steps/<N>/output.txt` (`1.4.5`) or `The tool's output was truncated due to being too long. You can find the full output in a file at file:///.../.system_generated/steps/<N>/output.txt.\n\nHere is a preview with the middle of the output truncated:\n...` (`1.5.3`). For `run_command`, the spilled `output.txt` body starts with `Command exited with code <N>.\n\nCommand output:\n` (or `The command exited with code <N>.\nOutput:\n`).
  3. On `tool_call_update(status="completed")` for `edit_file` (`code_action`), `agy` 1.5.3 (`ACPServer.getToolOutput` -> `GetCodeActionDiff` -> `unifiedDiffToOldAndNewTexts`) emits a `{ type: "diff", path, oldText, newText }` block containing the **entire file** before and after the edit, while omitting `rawInput` on the completion frame. If `boundText` (8,000-char tail slicing) runs on `diff.oldText`/`diff.newText` or if the full-file diff overwrites the `Target`/`Replacement` snippet from `tool_call`, edits in the upper/middle portion of a large file (> 8 KB) produce identical tail-sliced `old_string`/`new_string` with `[Earlier output truncated]` and lose the `+N/-M` line delta badge.
  4. Applying `[Earlier output truncated]` tail-slicing (`boundText` at 8,000 chars) or ACP `tool_result` head-slicing (`summary.slice(0, 4000)`) to `rawInput`, `rawOutput`, `content` blocks, MCP outputs, `Edit`/`Write` diffs, or Bash (`run_command`) outputs truncates terminal command outputs, corrupts `Edit` diffs, and breaks inline `widget_code` HTML/CSS/JS.
- **SuperOne code**: `apps/desktop/src/main/acp/antigravity-protocol.ts` (`sanitizeAntigravityToolInput`, `unwrapAntigravityToolOutputText`, `compactDiffPair`, `normalizeAntigravitySessionUpdate`), `apps/desktop/src/main/acp/acp-event-map.ts` (`shouldKeepFullToolResult`), `packages/acp/src/tool-result-map.ts` (`shouldKeepFullToolResult`)
- **Guard**: `apps/desktop/src/main/acp/antigravity-protocol.test.ts`

## 8. Mid-turn message queueing and native concurrent `session/prompt` Steer (observed in 1.5.3)

- **Behavior**:
  1. In `agy` `1.5.3` (`acpLanguageServer`), `(*ACPServer).Prompt` calls `(*Session).acquireTurn`: when a turn is already active (`turnDone != nil`), `isSteer` is `true`. Instead of rejecting concurrent prompts, `Prompt` sends `SendUserMessage` into the running cascade (`MessageHub` queues it for the next step boundary without cancelling active tools), calls `s.finishSteer()` to close the previous leg's `steerCh` so the earlier `session/prompt` RPC resolves immediately with `{ stopReason: "end_turn", usage: preSteerTurnUsage }`, and blocks in `s.awaitTurn(ctx, turnDone, steerCh)` until either another steer arrives or the cascade goes idle.
  2. Both `agy`'s wire `consumeTurnUsageLocked` (`idx > s.lastConsumedStep`) and SuperOne's SQLite step query (`idx > MAX(STEP_TYPE_USER_INPUT)`) reset per-turn token counters after the steered `USER_INPUT` step, so each steered bubble receives its own non-cumulative leg usage.
  3. SuperOne parks mid-turn sends in the host queue and exposes a single `Steer` action (`acp.steer_queued` -> `runtime.interject` -> `createAntigravitySteerablePrompt`), which dispatches the concurrent `session/prompt` without `session/cancel`, splits the live assistant bubble (`splitLiveAssistantAfterInterject`) without subtracting pre-steer usage from post-steer usage, and keeps `runtime.prompt` alive until the latest steered leg settles cleanly. If the steered `session/prompt` rejects before admission, the active leg stays alive and the queued message is restored.
- **SuperOne code**: `apps/desktop/src/main/acp/antigravity-steer.ts`, `apps/desktop/src/main/acp/antigravity-subagent.ts`, `apps/desktop/src/main/acp/acp-runtime.ts`, `apps/desktop/src/main/session/backends/acp-backend.ts`
- **Guard**: `apps/desktop/src/main/acp/acp-runtime-concurrent-turn.test.ts`, `apps/desktop/src/main/session/backends/acp-backend-queued-send.test.ts`

## 9. `write_to_file` / `multi_replace_file_content` permission frame vs. `code_action` execution step reconciliation (observed in 1.4.5 / 1.23.2)

- **Behavior**:
  1. During the permission hook (`AgyAdapter._permission_handler` / `_announce_tool_call_pending_and_in_progress`), Antigravity passes the model's true tool name (`write_to_file`, `replace_file_content`, or `multi_replace_file_content`) and full arguments (`TargetFile`, `CodeContent`, `TargetContent`, `ReplacementContent`, `ReplacementChunks`, `toolSummary`) and queues the generated `tool_call_id` under `session_info.pending_permission_frames[tool_name]`.
  2. However, when `localharness_external` executes any file mutation (`write_to_file`, `replace_file_content`, or `multi_replace_file_content`), it emits a `step.code_action` protobuf payload. `google.antigravity.connections.local.event_processor.PROTO_FIELD_TO_SDK_NAME["code_action"]` hardcodes `"code_action" -> "replace_file_content"`, and `LocalConnectionStep.from_dict` constructs `ToolCall(id="<trajectory_id>:<step_index>", name="replace_file_content", args={"file_path": "<path>"}, canonical_path="<path>")` with `step.content = toolSummary` and without `CodeContent`, `TargetContent`, or `ReplacementContent`.
  3. Unpatched `AgyAdapter._resolve_permission_frame` only checks `pending_permission_frames.get(str(call.name))` (`"replace_file_content"`), so `write_to_file` and `multi_replace_file_content` permission frames never reconcile: the `Write` card remains stuck in `in_progress` (`Writing...`) until turn end (when `AgyAdapter.prompt` marks leftover frames `failed` with `"Tool call was approved but never executed."`), while the `code_action` step opens a duplicate `Edit` card (`<trajectory_id>:<step_index>`) whose `rawInput` lacks diff fields and therefore renders only `step.content` (`toolSummary`, e.g. `"Write scratch/..."`) as its body.
  4. `_patched_resolve_permission_frame` and `_patched_stream_live_step` reconcile file-mutation execution calls across `_FILE_MUTATION_TOOLS` by normalized target path (falling back to earliest pending file-mutation frame) and restore the permission hook's original `call.name` and full `call.args` before streaming updates.
- **SuperOne code**: `apps/desktop/src/main/acp/antigravity-site-customize.ts`, `packages/shared/src/content-delta.ts`
- **Guard**: `apps/desktop/src/main/acp/antigravity-slash-and-usage.test.ts`, `packages/shared/src/content-delta.test.ts`

## 10. Cloud Code PA quota endpoint resolution (`daily-cloudcode-pa` vs `cloudcode-pa`) (observed in 1.4.5)

- **Behavior**:
  1. `agy_acp_server.par` (`google3/cloud/developer_experience/antigravity_extensions/acp_server/ccpa_connection/onboard.py`, `_determine_endpoint`) selects a single Cloud Code PA endpoint from the `v1internal:loadCodeAssist` response based on `paidTier.usesGcpTos`:
     - When `paidTier.usesGcpTos` is falsy (Consumer tiers: Free, Google AI Pro, Google AI Ultra), Antigravity connects to `https://daily-cloudcode-pa.googleapis.com` (`_PROD_DAILY_ENDPOINT`).
     - When `paidTier.usesGcpTos === true` (Enterprise / Workspace GCP ToS tiers), Antigravity connects to `https://cloudcode-pa.googleapis.com` (`_PROD_ENDPOINT`).
  2. Both endpoints accept the same OAuth access token and respond `200 OK` to `v1internal:retrieveUserQuotaSummary` and `v1internal:fetchAvailableModels`, but they maintain separate backend quota states (`cloudcode-pa.googleapis.com` can hold an independent or exhausted bucket from other Cloud Code surfaces while `daily-cloudcode-pa.googleapis.com` holds the active Antigravity consumer quota, e.g. `remainingFraction: 0.98` vs `0.02`).
  3. Querying both endpoints in parallel and merging windows by maximum `usedPercent` overwrites the active endpoint's real remaining quota with stale/exhausted values from the inactive endpoint. Quota probing must resolve the ordered endpoint list from `usesGcpTos` (`resolveAntigravityQuotaEndpoints`) and stop once the primary active endpoint returns quota windows.
- **SuperOne code**: `apps/desktop/src/main/acp/antigravity-usage.ts`
- **Guard**: `apps/desktop/src/main/acp/antigravity-protocol.test.ts`

## 11. `invoke_subagent`, backgrounded `run_command`, and `schedule` premature `end_turn`, unstreamed reactive wakeup, and pre-`user_message_chunk` replay (observed in 1.5.3)

- **Behavior**:
  1. In `agy` 1.5.3 (`acpLanguageServer`), asynchronous background execution spans three built-in tools:
     - `invoke_subagent` (accepting top-level `{ TypeName, Role, Prompt }` or `Subagents: [{ TypeName, Role, Prompt, Model, Workspace }]`) spawns child subagent conversations asynchronously.
     - `run_command` switches to a background task whenever command runtime exceeds `WaitMsBeforeAsync` (`500`–`10000` ms), appending a `GENERIC` step (`status: "RUNNING"`, which remains `"RUNNING"` permanently in the append-only transcript) containing `Tool is running as a background task with task id: <sessionId>/task-<stepIndex>` and `Task logs are available at: file:///.../.system_generated/tasks/task-<stepIndex>.log`.
     - `schedule` (`DurationSeconds` one-shot timer or `CronExpression` schedule) likewise spawns `<sessionId>/task-<stepIndex>` as a `GENERIC` `RUNNING` step.
  2. If the background task finishes while the parent trajectory is still generating an active step, `<SYSTEM_MESSAGE>` queues before the trajectory goes idle, `*streamFence` stays open, and `agy acp` streams `tool_call_update(status: "completed")` plus post-wakeup steps live on the ACP wire. However, once the parent trajectory finishes an interim status `PLANNER_RESPONSE` with no synchronous tool calls left running, `(*ACPServer).runPromptTurn` / `awaitTurn` sees the trajectory become idle, closes `*streamFence`, and resolves `session/prompt` with `PromptResponse{ stopReason: "end_turn" }` — leaving backgrounded `Bash` `tool_call` frames uncompleted on the wire (no `tool_result`) while the background task or subagent continues running.
  3. When the subagent (`send_message` / return) or background task completes later while `*streamFence` is closed, `acpLanguageServer` appends `<SYSTEM_MESSAGE>` (`sender=<sessionId>/task-<N>`, `priority=MESSAGE_PRIORITY_HIGH` for task completion/crash vs `priority=MESSAGE_PRIORITY_LOW` for explicit `manage_task(Action: "kill")` cancellation, which does not wake an idle planner) followed by post-wakeup `PLANNER_RESPONSE` (and any chained tool/task) step(s) to `<brainRoot>/<sessionId>/.system_generated/logs/transcript_full.jsonl`. Because no `session/prompt` RPC is open, `agy acp` neither streams those updates nor records them in `(*SessionState).RecordStepSeen`.
  4. On the user's **next** `session/prompt` call, `(*ACPServer).sendStepUpdatesWithMode` replays every unseen step in ascending `step_index` order — flushing `tool_call`, `tool_call_update`, `agent_thought_chunk`, `agent_message_chunk`, and `usage_update` notifications from the prior wakeup **before** emitting the new turn's `user_message_chunk`. Left unhandled, the background command's completion and post-wakeup assistant reply never appear when the command finishes and instead dump into the start of the next user turn's assistant bubble.
  5. SuperOne tracks subagents and background tasks per session: non-daemon (`IsDaemon !== true`) uncompleted `run_command` / one-shot `schedule` tasks and running subagents hold the turn open (`hasPendingAntigravitySubagentWakeup` / `waitForAntigravitySubagentWakeup`), stream live `.system_generated/tasks/task-<N>.log` output via `watchBashOutput`, backfill `Bash` `tool_use(status: "complete")` + `tool_result` (unwrapping spilled `.system_generated/steps/<N>/output.txt` files and exit codes) + `task_notification` upon `<SYSTEM_MESSAGE>`, and progressively stream post-wakeup `thinking`, `tool_use`/`tool_result` (including chained background tasks), `text`, and `message_usage` deltas. Long-lived `IsDaemon: true` (`run_in_background: true`) tasks do not block `end_turn`, and if one later exits or fires while the session is idle, `idleHooks` delivers an agent-initiated wakeup bubble. On the next `session/prompt`, `acp-runtime.ts` drops pre-`user_message_chunk` replay updates (`agent_thought_chunk`, `agent_message_chunk`, `tool_call`, `tool_call_update`, `usage_update`) before `normalizeAntigravitySessionUpdate` while `hasUnflushedAntigravityWakeupReplay` is set, clearing the flag on `user_message_chunk`.

## 12. Built-in `GENERIC` subhandler tools (`manage_task`, `manage_subagents`, `schedule`, `define_subagent`, `send_message`), MCP resource tools (`list_resources`, `read_resource`), and native `getToolKindTitleAndLocations` wire titles (observed in 1.23.2 / 1.5.3)

## 13. Unadvertised Streamable HTTP MCP transport in `initialize` (observed in 1.5.3)

- **Behavior**:
  1. `agy acp` `1.5.3` omits `agentCapabilities.mcpCapabilities` in its `initialize` response (`agentCapabilities` contains only `loadSession`, `promptCapabilities`, and `_meta.antigravity`, alongside `agentInfo: { name: "Antigravity ACP Server", version: "1.5.3" }`).
  2. Despite omitting `mcpCapabilities.http`, `acpLanguageServer` natively supports ACP `McpServerHttp` (`{ type: "http", name, url, headers }`) in `session/new` and `session/resume`, forwarding `Authorization` and `X-SuperOne-Session-Id` headers and maintaining stateful `mcp-session-id` across `initialize`, `notifications/initialized`, `tools/list`, and `tools/call` without spawning a per-session Node/Electron helper process.
  3. `readAgentCapabilities` and `mcpTransportCapsFromAgent` enable `mcp.http = true` when Antigravity is identified via `agentCapabilities._meta.antigravity`, `agentInfo.name`, or `agentId === 'antigravity'`.
- **SuperOne code**: `apps/desktop/src/main/acp/acp-capabilities.ts`, `apps/desktop/src/main/acp/acp-config.ts`, `apps/desktop/src/main/acp/acp-mcp.ts`
- **Guard**: `apps/desktop/src/main/acp/acp-capabilities.test.ts`, `apps/desktop/src/main/acp/acp-mcp.test.ts`
