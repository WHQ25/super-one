# Claude Agent SDK 0.3.285 → 0.3.287

Status: executed · Date: 2026-10-02 · Commit: —

## 1. Scope

0.3.286 and 0.3.287 (2026-10-01), at parity with Claude Code 2.1.287. 2.1.287
turns on Claude Code mods by default: plugins whose `hooks/hooks.json` names a
JavaScript/TypeScript hooks module that runs inside the CLI process. A user's
installed mods therefore start running in SuperOne sessions through
`settingSources: ['user', …]` with no opt-in.

This round absorbs the parts of mods an SDK host can see through stable wire
messages. Drawing mod UI (panes, the band above the prompt) is out of scope; see
backlog #12.

## 3. Surface diff

From `sdk.d.ts`. `sdk-tools.d.ts`, `bridge.d.ts`, `core.d.ts` and peer
dependencies unchanged.

| Change | Ledger row |
|---|---|
| `SDKControlGetTaskOutputRequest` (`get_task_output`) | `get_task_output` unused; backlog #13 |
| `sdkMcpServerManifestsOrigin`, `sdk_mcp_manifests_parked` | Not ledgered (initialize fields) |
| Result `first_text_post_queue_wait_ms`, `first_text_post_queued_behind` | Not ledgered; not read |
| `permissionMode` doc: omitted means Claude Code's default | `permissionMode` row unchanged |

Mods messages are absent from `sdk.d.ts`; their shapes come from the native
binary's schemas and the mods type declarations
(`mods/types/claude-code.d.ts` in the Claude Code repository):
`system/ui_log {plugin, text}`, `system/ui_toast {plugin, text, timeout_ms}`,
`system/ui_status {plugin, text | null}`, plus `ui_invalidate`, `ui_panes`,
`ui_scroll`, `ui_focus` for remote surfaces.

## 6. Verification

Live probe: SDK `query()` on the 2.1.287 binary with a local mod loaded through
`plugins`, `permissionMode: 'default'` and a denying `canUseTool`:

- `ui_log`, `ui_toast`, `ui_status` arrive as `system` messages; the ones raised
  in `session.start` arrive before `system/init`.
- A `tool.check` hook answering `{ decision: 'allow' }` ran `touch` without
  calling `canUseTool`.
- `$.prompt.submit` from `turn.complete` started a turn after the result:
  `command_lifecycle`, a second `system/init`, assistant frames, a second result.
- A hooks module that fails to load (a non-generator `turn.step` hook) does not
  appear in `plugin_errors`; the reason is only in the debug log.
- Loading a mod writes `.claude-plugin/types/` into the plugin directory.
- Steer probe (Bash `python3` sleeping 25 s, `priority: 'now'` after 4 s): see
  section 2.

Checks:

- `bun run typecheck:node`, `typecheck:web`, and `tsc --noEmit` in `apps/cli`,
  `apps/mobile`, `packages/claude`, `packages/chat-core`, `packages/chat-view`,
  `packages/runtime`: pass. `packages/shared` reports errors in
  `platform-registry/registry.test.ts` and missing node types in two files,
  none in files this change touches.
- Vitest: `packages/claude` (13 files), `packages/chat-core` (10),
