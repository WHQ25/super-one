# Claude Agent SDK 0.3.289 → 0.3.292

Status: executed · Date: 2026-10-07

## Scope

Upgrade the desktop, remote-node SDK and managed native runtime together, and
absorb the subagent task-event changes.

## Upstream changes

SDK 0.3.290–0.3.292 track Claude Code 2.1.290–2.1.292.
Source: [upstream changelog](https://github.com/anthropics/claude-agent-sdk-typescript/blob/main/CHANGELOG.md).

- 0.3.292: `agent_id` on subagent `assistant` / `user` messages; `parent_task_id`
  on `task_started` and `background_tasks_changed` entries; `run_id` on task
  events and `origin.runId` on task notifications; typed `ListAgents` result,
  SendMessage `recipient_kind`, `ReadNotifications` timestamps. A finishing
  task's `background_tasks_changed` now follows its `task_updated` and
  `task_notification`. Auto-mode subagents fall back to `canUseTool` when auto
  is unavailable. `suppressAlwaysAllowRule` is also set for connector tools an
  organization requires approval for.
- 0.3.290: WebFetch `offset`; failed Claude in Chrome results keep `_meta`;
  wildcard deny/ask rules cover `toolAliases`; partial-message streams always
  end with `message_stop`; resume metadata on turns a restarted worker continues.

## Surface diff

`sdk.d.ts` adds the optional fields above plus the `idleCompaction` setting;
`sdk-tools.d.ts` adds `OfferChromeSetup`, an `effort` input on Agent, WebFetch
`offset` and `ReadNotifications` timestamps. Inventory reports only the existing
`mcp_authenticate` / `mcp_oauth_callback_url` drift. The native mod protocol adds
`ui_prompt_autocomplete` (backlog #16); every name in `mod-surface/wire.ts` is
still present.

## Required changes

- [PLANNED] Bump all SDK/native pins and the managed runtime constant;
  regenerate the lockfile.
- [PLANNED] Re-key resumed subagent runs. A live probe showed 2.1.292 registers a
  SendMessage resume as a new `task_started` whose `tool_use_id` is the
  SendMessage call. `withSubagentResumeSignal` took that as "already registered"
  and stopped announcing the resume, so the phone's card, which tracks the Agent
  block id, stayed finished and the run's notification landed on the SendMessage
  row. The helper now rewrites every `task_*` event of a known subagent task to
  the Agent block id; its own announcement remains for CLIs that do not register
  the run. See [contracts](../contracts.md#a-resumed-subagent-run-is-named-by-the-sendmessage-call).
- [VERIFY] `background_tasks_changed` ordering. Both mappers handle `task_updated`,
  `task_notification` and `background_tasks_changed` as idempotent set updates;
  the live probe confirmed the new order and the deferred idle still fires once
  the set is empty.

## Adopted capabilities

- `suppressAlwaysAllowRule` already hides "always allow" in
  `claude-permissions.ts`; connector tools get it without code changes.
- `agent_id`, `parent_task_id`, `run_id`: not read (backlog #15).

  completion → SendMessage resume. Observed `agent_id` on every subagent frame,

  `tool_use_id` on the resumed run, and the new completion ordering.

  `CLAUDE_MCP_OAUTH_VERIFIED_SDK` bumped.

- `typecheck:node` passed. Claude package (121 tests, including mod recording
  replay), runtime harness tests (50, including the managed-pin lockstep),
  desktop MCP Apps (207) and query / warmup / backend / permissions /
  progressive / nested-subagent / resume-signal tests passed.
