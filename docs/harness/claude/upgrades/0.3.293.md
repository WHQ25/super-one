# Claude Agent SDK 0.3.292 → 0.3.293

Status: executed · Date: 2026-10-08

## Scope

Upgrade the desktop, remote-node SDK and managed native runtime together, and
pick up Haiku 5.5.

## Upstream changes

SDK 0.3.293 tracks Claude Code 2.1.293.
Source: [upstream changelog](https://github.com/anthropics/claude-agent-sdk-typescript/blob/main/CHANGELOG.md).

- Optional `subagent_type` on `background_tasks_changed` entries.
- Not in the changelog: the native catalog serves Haiku 5.5
  (`claude-haiku-5-5`) behind the `haiku` alias, with effort
  (`low`…`max`, including `xhigh`), adaptive thinking and auto mode. Haiku 4.5
  stays listed as `claude-haiku-4-5-20251001` without effort.

## Surface diff

`sdk.d.ts` adds `subagent_type` and two `SDKStartupFailureReason` values,
`org_config_required_unavailable` and `org_config_refused`; `sdk-tools.d.ts` is
unchanged. Inventory reports only the existing `mcp_authenticate` /
`mcp_oauth_callback_url` drift. Every `ui_*` name in `mod-surface/wire.ts` is
still in the native binary.

## Required changes

- [DONE] Bump all SDK/native pins and the managed runtime constant;
  regenerate the lockfile.
- [DONE] Remote-node fallback catalog (`DEFAULT_CLAUDE_MODELS` in
  `apps/cli/src/provider/resolve-service.ts`) moved from the 4.5 family to
  Opus 5.5 / Sonnet 5.5 / Haiku 5.5 with the probed effort levels. Desktop and
  node probes read `supportedModels()`, so Haiku 5.5 needs no other change.

## Adopted capabilities

- `subagent_type`: not read (backlog #15).
- New startup failure reasons: still shown as generic text (backlog #6).
