# Claude Agent SDK 0.3.296 → 0.3.300

Status: executed · Date: 2026-10-15

## Scope

Upgrade the desktop, remote-node SDK and managed native runtime together. No
new capability is adopted.

## Upstream changes

SDK 0.3.300 tracks Claude Code 2.1.300; 0.3.297 and 0.3.298 are parity-only
releases. Source: [upstream changelog](https://github.com/anthropics/claude-agent-sdk-typescript/blob/main/CHANGELOG.md).

- 0.3.300: `canUseTool` no longer sets `suppressAlwaysAllowRule` for connector
  tools an organization requires approval for (reverts 0.3.292); the field
  itself stays.
- 0.3.300: `thinking: { type: 'disabled' }` and `maxThinkingTokens: 0` run as
  adaptive thinking on models that cannot turn thinking off.
- 0.3.300: `updatedInput` from PreToolUse and PermissionRequest hook callbacks
  is validated like model input and unknown keys are dropped; `canUseTool` is
  unchanged.
- 0.3.300: a background subagent's final report in auto mode always runs as its
  own turn.
- 0.3.299: `elicitation` control requests carry `property_order`; CronCreate
  and CronList outputs carry `nextFireAt`.
- 0.3.299: queued user messages with content-block arrays merge with a line
  break; `origin.body` is omitted when several queued peer messages merge.
- 0.3.299: reserved MCP server names (`__proto__` and the legacy accessor
  names) are refused by `initialize`, `mcp_set_servers` and `claim_session`.
- Fixes in `importSessionToStore`, `rewind_conversation`, and in-process SDK MCP
  servers on a claimed `prewarm()` process.

## Surface diff

`sdk.d.ts` adds `property_order` on the elicitation request and four usage
`behaviors` keys (`max_effort`, `workflow`, `always_on_context`,
`large_tool_results`); the rest is doc comments. `sdk-tools.d.ts` adds `owned`
on Artifact results and `nextFireAt` on Cron outputs. The inventory reports only
the existing `mcp_authenticate` / `mcp_oauth_callback_url` drift. Every `ui_*`
name in `mod-surface/wire.ts` is still in the native binary.

## Required changes

- [DONE] Bump all SDK/native pins, the managed runtime constant and both
  verified-SDK constants; regenerate the lockfile.
- [VERIFY] `suppressAlwaysAllowRule` revert: `claude-permissions.ts` still reads
  the field, so connector tools an organization requires approval for show
  "always allow" again when the SDK sends suggestions. No code change.
- [VERIFY] Hook `updatedInput` validation: SuperOne's only PreToolUse hook
  (`denySubagentSessionRename`) denies without `updatedInput`, and no
  PermissionRequest hook is registered. Every `updatedInput` goes through
  `canUseTool`.
- [VERIFY] Thinking: every runtime passes `thinking: { type: 'adaptive' }`.
- [VERIFY] Reserved MCP server names: SuperOne's server names are fixed
  identifiers or user config keys; none is reserved.

## Adopted capabilities

None. `property_order` is backlog #19. Cron `nextFireAt` renders through the
generic tool row; `rewind_conversation` and `importSessionToStore` are unused.
