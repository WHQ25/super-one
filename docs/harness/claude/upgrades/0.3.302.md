# Claude Agent SDK 0.3.300 → 0.3.302

Status: executed · Date: 2026-10-18

## Scope

Upgrade the desktop, remote-node SDK and managed native runtime together, and
add per-tool permission rules to the desktop MCP settings tool list.

## Upstream changes

SDK 0.3.302 tracks Claude Code 2.1.302. Source: [upstream changelog](https://github.com/anthropics/claude-agent-sdk-typescript/blob/main/CHANGELOG.md).

- 0.3.301: sdk-type MCP server configs take `tools[]` entries with
  `permission_policy` `always_ask` / `always_deny`, read on `initialize` and
  `setMcpServers()`. http/sse servers already carried the field on
  `mcp_set_servers`; stdio servers have none. The CLI turns every policy into
  ordinary ask/deny rules on `mcp__{server}__{tool}`.
- 0.3.301: `BUILTIN_TOOL_NAMES` and `LEGACY_TOOL_NAME_ALIASES` exports (alpha).
- 0.3.301: `reloadPlugins({ addPlugins })` loads more plugin folders into a
  running session.
- 0.3.301: `setModel()` with a model ID applies while the account is at a usage
  limit; a full disk during login refresh reports `invalid_request` with
  `api_error_status: null` instead of `authentication_failed` / 401.
- 0.3.301: `mcpServerStatus()` still reports `_meta.ui.visibility` when the rest
  of `_meta.ui` fails validation.
- 0.3.302: a structured-output result the API refused is an error without
  `structured_output`.
- 0.3.302: an omitted `permissionMode` starts in `default` on third-party
  providers, with telemetry off, or on a fresh install.
- 0.3.302: fork subagents (`subagent_type: "fork"`) are on by default in SDK
  sessions; `CLAUDE_CODE_FORK_SUBAGENT=0` turns them off.

## Surface diff

`sdk.d.ts` adds the two exports, `tools?: McpServerToolPolicy[]` on
`McpSdkServerConfig` and on the initialize `sdkMcpServerConfigs` entries,
`addPlugins` / `add_plugins` on plugin reload, and `result_not_for_model` on
`mcp_call`. `sdk-tools.d.ts` only documents that `effort` is ignored for forks.
The inventory reports the two new exports plus the existing
`mcp_authenticate` / `mcp_oauth_callback_url` drift. Every `ui_*` name in
`mod-surface/wire.ts` is still in the native binary.

## Required changes

- [DONE] Bump all SDK/native pins, the managed runtime constant and both
  verified-SDK constants; regenerate the lockfile.
- [VERIFY] `permissionMode` default change: every runtime passes it explicitly
  (`'default'` fallback in `claude-live-session.ts` / `run-sdk-turn.ts`, desktop
  `buildClaudeOptions`).
- [VERIFY] Structured output: `agent-event-mapper.ts` reads
  `structured_output` only when present; a refused result now maps as an error.
- [VERIFY] Fork subagents: the Agent tool row renders any `subagent_type`; a
  fork arrives as an ordinary Agent call.
- [VERIFY] Usage-limit `setModel` and the login-refresh error: SuperOne matches
  neither `authentication_failed` nor the 401 status.

## Adopted capabilities

- Per-tool MCP permissions in Settings → Harnesses → MCP (Claude only, local
  projects). The UI writes Claude Code permission rules
  (`permissions.allow|ask|deny` with the exact `mcp__{server}__{tool}` name) instead of
  `permission_policy`: user MCP servers reach the CLI through `settingSources`,
  not `mcpServers`, and stdio servers cannot carry a policy, while rules cover
  every transport and claude.ai connectors. See
  [contracts](../contracts.md#mcp-tool-permission-rule-names). Implementation:
  `packages/runtime/src/fs/mcp-tool-permissions-claude.ts`,
  `apps/desktop/src/renderer/src/components/McpDetailPage.tsx`.
- `permission_policy` on SuperOne's own sdk server, `BUILTIN_TOOL_NAMES` and
  `addPlugins` are backlog #20–#22.
