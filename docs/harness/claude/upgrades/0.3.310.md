# Claude Agent SDK 0.3.302 → 0.3.310

Status: executed · Date: 2026-10-24

## Scope

Upgrade the desktop, remote-node SDK and managed native runtime together. The
same change closes the MCP elicitation and returned-file gaps found while
reading this range (they do not depend on the bump; see
[contracts](../contracts.md#mcp-elicitation-url-consent-and-withdrawal)).

## Upstream changes

SDK 0.3.310 tracks Claude Code 2.1.310. Source: [upstream changelog](https://github.com/anthropics/claude-agent-sdk-typescript/blob/main/CHANGELOG.md).

- 0.3.304: browser SDK `suspendSseStream` / `resumeSseStream`;
  `getContextUsage()` rows gain a stable `id`, and on stdio hosts `mcpInstructions`
  per server, `pluginId` and file `path` on agents and skills.
- 0.3.304 / 0.3.305: `startup()` no longer counts SessionStart / Setup hook time
  against its 60 s limit when no `initializeTimeoutMs` is passed, keeps only the
  newest `hook_progress` per hook, and words its timeout error by cause;
  `initializeTimeoutMs: null` now means the default.
- 0.3.305: `get_usage` behavior windows add `recommendations` and a `fix` action.
- 0.3.305: servers set with `setMcpServers` are no longer replaced later by a
  same-named server from the user's settings.
- 0.3.307: `command_lifecycle` `started` frames of a scheduled wakeup or task
  carry `wakeup_source` (and `scheduled_for` for a wakeup); browser SDK
  `supportedDialogKinds`.
- 0.3.309: host `managedSettings` keep `disableAllHooks`,
  `disableSkillShellExecution` and empty HTTP-hook lists; `extractFromBunfs()`
  extracts into a per-user temp directory and reuses a file only when its bytes
  match.
- Claude Code 2.1.303–2.1.310, SDK-relevant: an MCP call that times out in a
  non-interactive session while its elicitation is unanswered now tells the model
  not to retry; a disabled MCP server is no longer reconnected by a later
  permission prompt; `setModel()` waits up to 15 s for the API; model switches,
  messages and interrupts no longer wait behind a context-usage check; faster
  resume of large compacted sessions; lower compaction memory in SDK sessions.

## Surface diff

`sdk.d.ts` adds fields only: `getContextUsage` row `id`, `mcpInstructions`,
`pluginId` / `path`; `get_usage` `recommendations` / `fix`; `liveReply` on
`mcp_status`; `allowNestedUserNamespaces` (sandbox), `attributionProject`,
`attributionProjectPolicy` and `sshHostCommands` settings; the `startup()` /
`prewarm()` timeout doc. `agentSdkTypes.d.ts`, `sdk-tools.d.ts` and `core.d.ts`
are unchanged. The inventory reports no new names; its two drift items
(`mcp_authenticate`, `mcp_oauth_callback_url`) predate this bump. The MCP task
and elicitation surface is identical to 0.3.302. Every `ui_*` name in
`mod-surface/wire.ts` is still in the native binary.

## Required changes

- [DONE] Bump all SDK/native pins, the managed runtime constant and both
  verified-SDK constants; regenerate the lockfile.
- [VERIFY] `startup()` timing: `warmup-manager.ts` passes no
  `initializeTimeoutMs`, so it gets the hook-time exemption; nothing reads the
  old timeout wording.
- [VERIFY] `extractFromBunfs()` / `managedSettings` / `setMcpServers`: SuperOne
  calls none of them (it passes `pathToClaudeCodeExecutable` and MCP servers at
  spawn).
- [VERIFY] `getContextUsage()`: `claude-backend.ts` forwards categories by name
  for display only, so the new `id` is not needed.
