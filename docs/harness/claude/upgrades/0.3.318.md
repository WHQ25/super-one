# Claude Agent SDK 0.3.310 → 0.3.318

Status: executed · Date: 2026-11-06

## Scope

Upgraded the desktop SDK, remote-node SDK, eight native binary packages and
managed runtime together from 0.3.310 to 0.3.318. The assessment was prepared on
2026-11-05; implementation and checks completed on 2026-11-06.
At assessment time, the npm `latest` tag was 0.3.318 (Claude Code 2.1.318), published
2026-11-03T21:55:44.877Z. `next` was 0.3.319 and is outside this plan.

## Surface diff

- Package exports, peer dependencies and normal Query method signatures are
  unchanged. `./core` adds the `prewarm` export. No main-entry runtime export,
  Options key, hook-event name or control-request subtype was removed.
- The Messages ledger gains `system/session_writes_lost`. Result types gain
  `credential_expires_at`; ModelUsage gains optional cache-lifetime counters.
- `HookCallbackMatcher` and the initialize hook wire gain `onFailure`;
  initialize responses gain `hook_on_failure_supported`. The SDK refuses a
  fail-closed hook configuration when the runtime cannot honor it or does not
  register those hooks. Do not catch that refusal and silently retry fail-open.
- Startup reasons gain `sandbox_required_unavailable`, `initialize_not_first`
  and `config_file_invalid`. Current `result-failure.ts` preserves subtype and
  terminal reason but not `startup_failure_reason`.
- Control responses add optional `pending_elicitation_requests` for clients
  joining an already-initialized process. Current stdio sessions own their
  processes; there is no direct attach/replay feature to implement here.
- Settings also add `workingDirectoriesAsGiven`, `disableReplyCheck`,
  marketplace `pluginDigests`, and auto-mode fields; permission-rule sources add
  `mcpMount`. Existing settings handling does not need new UI for every field.
- Tool types also add task `toolsUsed`, artifact pagination/provenance and
  project metadata, Bash `backgroundWakesOwner`, and Grep/Glob `timedOut`.
  `./sdk-tools` is unused, so the removed Read variant is not an identified
  compile-time blocker. Runtime presentation still needs regression coverage.

The [API ledger](../api-surface.md) now describes 0.3.318 and passes the
inventory. Two pre-existing untyped OAuth requests were moved out of the typed
control union into its private-control section. Native Mod UI schema comparison
also found optional `ui_attach.draws` and `ui_prompt_paint`; SuperOne does not
advertise these opt-ins (backlog #30).

## Adopted capabilities

- [DONE] Upgraded to the stable runtime and closed the informational/persistence
  notice gaps, authorization hook failure behavior and startup diagnostics.
- [VERIFY] Existing desktop/node fixtures covered model/Stop controls,
  `priority: now/next` steering, warm starts and resume; native local probes
  covered MCP Apps/auth and the Mod UI adapter with official example mods.
- [VERIFY] Task activity derives from task events/status, never the timing of
  `task_progress.summary`; allow a missing summary on a completed task.
- [DEFERRED] AskUserQuestion `unanswered`: add `skipped`, `replied_in_chat` and
  `dismissed` to shared annotations, retain init capabilities in each runtime,
  and gate SDK submission by capability. The model still needs text in
  `answers`; the annotation itself is not visible to it. An old runtime must
  keep the existing answer/deny behavior.
- [DEFERRED] Preserve the optional per-model cache-lifetime counts through
  `buildClaudeResultMetadata` and shared usage types if adding detailed usage
  reporting. They are subsets of the aggregate, may undercount older turns,
  and must not be added to the aggregate again. Keep upstream `costUSD`.
- [DEFERRED] `credential_expires_at`: associate it with the selected credential
  domain, not every account. It describes the stored login's refresh-chain end,
  can be an estimate, and is not the access-token expiry or proof of validity.
- [DEFERRED] New permission controls: evaluate separately before exposing
  settings. The write boundary covers file tools, not shell/MCP/hooks/memory,
  and disables EnterWorktree/ExitWorktree. Read exemptions are host-only,
  literal validated absolute paths, not glob patterns or new working folders;
  they do not change OS sandbox access. Do not enable these globally in this
  upgrade, especially around SuperOne's worktree creation.
- [DEFERRED] Alpha `prewarm().claim()`, browser/bridge clients and unrelated
  settings editors. Retain the existing startup pool and shared event model.

## Review follow-up: shutdown delivery and retry

Date: 2026-11-06 · Reviewer: Claude (`claude-base`)

The independent review found that mapping an exit notice did not ensure its
delivery: SDK `close()` discards its reader before the native process emits
`session_writes_lost`. It also found a second SDK exception overwriting a startup
result's recovery details, and system rows being counted as new completions.
New regressions reproduced these issues before the fixes.

Desktop and node now stop accepting input, interrupt/cancel pending SDK work,
end the input generator and drain only notices before final close/abort. The
three-second deadline leaves room for the native persistence flush's two-second
wait. It is bounded best effort: a hung or slower shutdown can still lose its
last warning. Retired entries keep their own event sink, including through node
and desktop shutdown; replacements wait for the old release. Late tool permission
and elicitation callbacks cannot reopen prompts during desktop teardown.

Startup results retain their structured reason and original recovery text when
the SDK subsequently throws. An unsupported fail-closed hook runtime receives
an update hint; the hook stays enabled. The text-matching fallback has an SDK
version guard because the upstream error has no stable code. Process exit now
retires desktop runtime handles, allowing retry after repairing configuration.
That retry regression also failed before the handle cleanup was added.

Notices no longer change recency, restart the chat activity clock, or replace the
last assistant completion used for unread tracking. Generated storage warnings
and the details disclosure are translated; upstream informational text stays
literal. The review withdrew the proposal to suppress `info`: SuperOne exposes
a transcript, and no real duplicate-progress example was found. `tool_use_id`
is preserved in diagnostics; grouping remains unimplemented pending evidence.

### Final review disposition

Claude's third review reported no blockers. One small concurrency follow-up was
also reproduced: send arriving first during an old runtime's release could race
a settings rebuild and make that rebuild fail with `already started`. All rebuild
paths now publish their latch, and revive rechecks it after waiting for release.
Deterministic regressions cover both arrival orders and one replacement using
the changed cwd; concurrent settings rebuilds serialize through the same latch.
The affected backend/query/bridge files passed again (194 tests), along with
desktop main typechecking and whitespace checks. This adds two regressions to
the verification above, for 605 affected tests across the final review checks.

The review's older unexpected-exit queue/terminal-state concerns are recorded as
a separate suggested task, `f598f99d-e59a-4c85-bb8c-b10657febc04`, to reproduce
and address independently. They do not block this upgrade. Live OAuth with
custom headers and concurrency stress beyond the deterministic regressions
remain unverified.
