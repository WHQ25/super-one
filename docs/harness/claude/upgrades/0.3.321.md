# Claude Agent SDK 0.3.318 → 0.3.321

Status: executed · Date: 2026-11-10

## Scope

Upgraded the desktop SDK, remote-node SDK, eight native binary packages and
managed runtime together from 0.3.318 to 0.3.321. npm `latest` and `next` were
both 0.3.321 (Claude Code 2.1.321), published 2026-11-09T19:03:36.409Z.
0.3.319 is on npm; 0.3.320 is in the changelog and was not published as its
own tarball.

Sources checked:

- [SDK changelog](https://github.com/anthropics/claude-agent-sdk-typescript/blob/main/CHANGELOG.md)
- Published npm tarballs for 0.3.318 and 0.3.321, comparing declarations after
  comment stripping

## Upstream changes

Tags describe SuperOne relevance: `[impact]` needs host work to expose or adopt;
`[benefit]` comes from the runtime bump; `[none]` has no current consumer.

| Version | SDK change | Tag and SuperOne relevance |
|---|---|---|
| 0.3.319 | MCP tasks in SDK sessions when `CLAUDE_AUTO_BACKGROUND_TASKS=1` and input is streaming, with `task_type` `"mcp_task"` | [benefit] Existing task events already carry that type. SuperOne does not set the env var. |
| 0.3.319 | `session_writes_lost` only when the CLI exits 0; an error exit keeps the stderr line | [impact] Update the contract. Existing mappers still apply when the message arrives. |
| 0.3.319 | `deleteSession()` rejects with `ENOTEMPTY` if the session folder cannot be fully removed | [none] SuperOne deletes forked transcripts directly and does not call this helper. |
| 0.3.319 | OpenTelemetry no longer counts an unclaimed `prewarm()` | [none] SuperOne does not use `prewarm()` or that metric. |
| 0.3.320 | Runtime parity only | [benefit] No SDK API adoption. |
| 0.3.321 | `canUseTool` no longer receives this app's own PreToolUse reason as `decisionReason` | [benefit] Permission copy stays the tool's reason. |
| 0.3.321 | A PreToolUse `ask` is no longer dropped when another hook's `defer` finishes first | [benefit] The permission bridge still answers `canUseTool`. |
| 0.3.321 | One `undefined` entry in `hooks` no longer drops every hook | [benefit] Desktop and node pass defined matchers only. |
| 0.3.321 | `WarmQuery.query()` with a string prompt no longer hangs after `startup()` plus `resume` when that process already finished a turn | [benefit] Desktop warm start uses `startup()` then `query()`. |
| 0.3.321 | Queued subagent reports in auto mode share one model call; all but the last end in an empty `result` with `num_turns: 0` | [benefit] The node already ignores an untagged `num_turns: 0` success before streamed text on resume. Do not treat a missing summary as completion. |
| 0.3.321 | `reloadPlugins()` / `system/init` keep project skills after entering a worktree that lacks them | [benefit] Desktop reloads plugins in a live session. |
| 0.3.321 | `setMcpServers` no longer closes a folder server of the same name after `SpareProcess.claim()` | [none] Neither API is used. |
| 0.3.321 | An SDK MCP server named `claude-in-chrome` follows the org Chrome policy | [none] The in-process server is named `superone`. |

## Surface diff

Comment-stripped declarations:

- `sdk.d.ts` adds optional `mcp_call.check_permissions`, control request
  `set_has_subscribers`, settings `permissions.denyInsteadOfPrompting`, and
  Windows-only managed setting `disableWindowsBashCommandSplit`.
- `sdk-tools.d.ts` adds optional `CronDeleteOutput.endedLoopWakeup`. SuperOne
  does not import `./sdk-tools`.
- `bridge.d.ts` adds terminal reason `session_security_tier_below_org_policy`.
  SuperOne does not use the browser bridge.
- `agentSdkTypes.d.ts`, `core.d.ts` and `browser-sdk.d.ts` are unchanged.
  Package exports, Options keys and Query methods are unchanged.
- `HookCallbackMatcher.onFailure` was already on the 0.3.318 host type, and
  `buildInitializeRequest` already copied it. The refusal sentence is longer;
  the prefix matched by `buildClaudeThrownFailure` is unchanged.
- Native darwin-arm64 2.1.321 adds `ui_notify`, `ui_notify_cancel` and the
  terminal watchdog string `startup_ui_never_appeared`. No name in
  `mod-surface/wire.ts` disappeared.

The [API ledger](../api-surface.md) describes 0.3.321. `set_has_subscribers` is
the new control-request row.

## Adopted capabilities

- [DONE] Stable runtime 0.3.321, and fail-closed behavior for the desktop
  subagent authorization hook.
- [VERIFY] Existing result, notice, warmup and permission tests. Task activity
  still comes from task events, not from when a summary arrives.
- [DEFERRED] `mcp_call.check_permissions` (backlog #31). Leave View calls on
  the trusted control path.
- [DEFERRED] `set_has_subscribers` (backlog #32). Do not set the stream-event
  hold variables.
- [DEFERRED] `permissions.denyInsteadOfPrompting` (backlog #33, rejected for
  the default). It would stop `canUseTool` from being asked.
- [DEFERRED] `disableWindowsBashCommandSplit`. Managed settings only, and
  SuperOne does not write that policy.
