## 3. Surface diff

Generated stable and experimental schemas from both exact-version binaries. Stable client requests: 102→104; experimental client requests: 164→167; stable server requests remain 10 (11 with experimental); server notifications: 82→83.

- Removed: `thread/rollback`; the shared fork helper's legacy fallback is migrated to `thread/turns/list` + `thread/fork.beforeTurnId`.
- Added stable requests: `account/gatewayOAuth/{login,read,cancel}`; notification: `account/gatewayOAuth/changed`.
- Added experimental request: `rollout/compress`.
- Added fields and shape changes: item-anchored `thread/items/list` cursors, `ThreadResumeResponse.collaborationMode`, saved `disabledPluginIds`, `McpResourceReadParams.target`, `McpServerStatus.httpOrigin/serverCapabilities`, `ThreadRealtimeStartParams.backendReasoningStatus`, `PluginDetail.onboardingSkill`, image `fileId` input, item lifecycle timestamps, model access programs, gateway/workspace routing, and enterprise login/provider requirements. Their client calls/handlers are recorded in [api-surface.md](../api-surface.md).
- MCP tool items add `mcpAppUi { resourceUri, preferredModelDisplayMode }`; legacy appContext/mcpAppResourceUri remain available. Both current item mappers tolerate the added field; a complete MCP Apps projection is deferred.
- Image inputs now accept either URL or uploaded file ID. Existing URL/local-image calls remain valid; no new file-ID input path is added.
- `CodexErrorInfo` adds `flexUnavailable` and `tooManyDenials`; the existing generic error-code parser preserves new names. `PlanType` adds `promax`.
- Enterprise config requirements add login/provider constraints and replace the Windows implementation enum. SuperOne reads requirements as a record and only enforces its existing managed capability fields; Windows-specific client settings remain unused.
- `disabledPluginIds` is explicitly documented as saved state that does not yet filter capabilities. It is not exposed as a working enable/disable control.
- No server-request methods or chat-item kinds were added or removed. Unknown optional fields continue to be tolerated; unsupported inbound requests keep their existing safe rejection behavior.
