## 3. Surface diff

Tagged TypeScript protocol adds `thread/attachmentOwner/list` and
`thread/prediction/updated`; no request or notification method was removed.
`TurnStartParams` gains optional `parentTurnId` / `rootTurnId`, `Turn` gains
nullable `rootTurnId`, and subagent activity gains nullable model/effort metadata.
`ModelProviderCapabilitiesReadResponse.namespaceTools` is removed (unused here).
`CodexErrorInfo` accepts unknown string/object variants.
Exact npm schemas contain 317 stable files (was 314) and 447 experimental files
(was 440). Stable requests add `thread/attachmentOwner/list`; experimental
requests also add `account/bedrock/checkGovCloudRequirements` and
`thread/prediction/request`. Notifications add `thread/prediction/updated`.
No methods or schema files were removed. Existing response readers tolerate
the new optional/nullable fields and unknown error variants; the removed
provider capability field has no consumer.

## 5. Adopted capabilities

Runtime fixes and prediction notification reception. The shared adapter observes
turn boundaries on the persistent connection rather than inside a finished
turn's inbox. It accepts the latest successful root source turn, invalidates
before a new full input, and clears failed/null/blank results. Desktop and remote
node connections emit the existing shared `prompt_suggestion` event; node uses
the ambient session sink after the request's abort scope ends. Desktop reuses
ghost text / Tab-to-fill and mobile reuses tappable suggestions, without replacing
a nonempty draft or sending automatically. The three duplicated desktop dispatcher
setups are consolidated in `codex-session-dispatcher.ts`.

No prediction generation capability is advertised and no prediction request or
extra model call is sent: the pinned server cannot produce suggestions.
