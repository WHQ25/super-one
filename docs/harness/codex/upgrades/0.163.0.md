Status: executed · Date: 2026-10-17

## 1. Scope

Upgrade the stable bundled and managed runtime to `@openai/codex` 0.163.0,
adopt its dedicated v3 voice catalog, and separately record newer App Server
changes on upstream `main`. The latter remain a follow-up watchlist.

## 2. Upstream changes

Tags: `[impact]` means client adaptation or a compatibility gate; `[benefit]`
means an upstream runtime improvement; `[none]` means no proposed client work.
Optional features remain deferred unless explicitly listed as adopted.

Two release-note details need the exact current baseline:

- `instant_interrupt` is already `default_enabled: true` in both 0.162.1 and
  0.163.0. The material feature-default change is `code_mode_interrupt`, from
  under-development/off to stable/on. Regress cancellation of active cells and
  nested tools, pending forms and the next queued turn.
- Selected built-in read-only tools (skills, memories, conversation history,
  plugin/agent listings, clock/context and goal reads) opt into parallel
  execution. Goal mutations remain serialized. This is a runtime benefit, not
  a request to parallelize every host tool or widen SuperOne tool admission.

### Follow-up implementation when a stable release includes main changes

1. Normalize image generation in one Electron-free helper under
   `packages/codex/src`, reused by `agent-event-mapper.ts` and desktop
   `codex-turn.ts`. Cover live events, sparse updates, history/replay, child
   items and compact mobile projection. Preserve `savedPath` and failure/timing
   metadata; optionally map `inputImages[].path` to existing reference paths.
   Do not add another broad mapper to the already-large desktop turn module.
2. Decide whether the product supports provider-only images without a readable
   local file. If yes, resolve using the originating provider/account/node and
   existing file delivery; never treat opaque `fileId` as a local path or use an
   unrelated OpenAI Files endpoint without a supported contract. Otherwise show
   an explicit completed-but-unavailable state. This is a separate capability,
   not a prerequisite for normal `savedPath` results.
3. Forward host-owned `RealtimeVoiceHost` call identity as `voiceSessionId` via
   internal session/backend start options. The host currently generates a UUID
   before starting upstream; reuse it rather than creating an unrelated ID in
   each layer or changing `realtimeSessionId`.
4. Add account-transition and compressed-history regressions; preserve current
   cache invalidation and explicit resume policy. Treat metadata patching,
   unread receipts, native item hydration and dynamic MCP catalog refresh as
   independent feature decisions.
