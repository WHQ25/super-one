# Codex 0.165.0 → 0.167.0

Status: executed · Date: 2026-11-06 · Commit: not committed

## 1. Scope

Upgrade the desktop dependency and managed runtime from `@openai/codex` 0.165.0
to stable 0.167.0. Implement desktop managed human checkpoints, provider-resolved
interaction cleanup on both hosts, structured desktop MCP tool identification,
recorded reasoning/image timing and native-dollar usage parsing. Keep remote
native command approvals explicitly unsupported.

npm `latest` was **0.167.0** at lookup; `alpha` was `0.168.0-alpha.7`.
The npm publication times are 2026-10-29 19:56 UTC for 0.166.0 and
2026-11-06 01:46 UTC for 0.167.0. The latter is November 5 in Los Angeles.
Target the stable release, without following alpha.

## 8. Remote native approval completion

Completed: 2026-11-06. This follow-up supersedes the initial remote-native-approval
deferral in sections 1, 3 and 5; the other deferred capabilities stay deferred.

- The shared client has an explicit native command/file approval handler and
  advertises `requiredHumanApproval` only when it is installed. Its wire responder
  enforces valid one-time decisions for human checkpoints even if a host returns
  a persistent decision.
- Production nodes use a session-owned provider-permission callback on the
  existing `SessionRuntime` waiter, snapshot/event log and lease-gated response.
  Command previews, requested paths and network destinations reach the existing
  desktop/phone permission UI. Codex owns native session grants; the host does
  not save them as blanket Bash grants.
- Child approval routing validates bounded provider ancestry without resuming a
  running child. Native prompts are FIFO. The handler survives root completion
  for child work and is installed before resume, saved View activation or a
  voice-first session. Active/idle Stop cancels pending and queued approvals;
  provider resolution, turn completion and disconnect reject stale decisions.
- Shared desktop/native mapping remains aligned through `native-approval.ts`.
  Administrative clients without a handler continue to reject interactive work;
  production remote sessions now support these native approvals.

## 10. Independent approval and Session idle Stop entrypoint

Claude's 2026-11-06 re-review **approved the code review**, closed blockers #1
and #2 and findings #3–#9, and found no new blocker. Its probes used the real
runner and SessionRuntime with fake stdio, including mixed native/MCP requests,
a new voice-only checkpoint after Stop, real spawn-source ancestry, decision
reason retention and additional-grant persistence rejection. The reviewer did
not rerun the listed suites/typechecks or perform live acceptance.

The reviewer found #10 was only partially closed: `Session.interrupt()` returned
early when not streaming, before it could reach `CodexBackend.interrupt()` and
the fixed native cancellation path. Follow-up Session tests reproduced this
for both idle and ended sessions with a pending checkpoint, failing with a
false interrupt result. The entrypoint now also admits backend-owned pending
interactions and restores its prior idle/ended state after cancellation. An idle
session without a pending interaction still returns false. The two affected
Session/turn files pass **393 tests** after the fix. This last small entrypoint
change was verified by the implementing agent; it postdates Claude's approval.

Remaining non-blocking review observations:

- A harness that abandons an interaction without sending abort/resolution can
  leave that visible prompt ahead of later prompts. Explicit host resolution
  remains the interaction queue's ownership contract.
- Child origin validation precedes runtime admission, so a later root prompt
  can appear first while a child ancestry read is pending.
- Persistent approval options follow provider `availableDecisions`; a real
  provider may offer fewer session-grant choices than the old UI did.

Code review approval does not establish real remote model/managed-command,
physical controller, running-child `thread/read`, long voice-call or real
provider resolution-order acceptance. Those live checks remain unverified.

Final entrypoint validation: desktop main typecheck and `git diff --check`
passed after the Session change.
