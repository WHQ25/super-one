# SORP — SuperOne Registry Protocol

**Version:** v0.1 (Draft) **Status:** Working draft. Subject to change before v1.0. **Last updated:** 2026-05-24 **License of this document:** CC0-1.0

---

## 1. Abstract

SORP is a vendor-neutral specification for distributing AI agent resources — MCP servers, skills, mini-apps — and pointers to other resource catalogs ("registries"). Inspired by Homebrew taps and Helm chart repositories, SORP is **Git-based, decentralized, and zero-infrastructure for publishers**. Authors keep their source code in their own repositories; taps only carry metadata.

## 2. Goals

- Vendor-neutral metadata format usable across AI harnesses (Claude Code, Codex, SuperOne, …).
- Distribution via plain Git repositories — no central service required.
- Authors retain ownership of their source code; taps only cache metadata.
- Pluggable trust model (`official` / `community` / `private`).
- Predictable client-side aggregation of multiple taps.
- Open enough that any party can self-host a tap or implement a client.

## 3. Non-Goals

- Not a package manager — no binary hosting; transport security is Git's responsibility.
- Not a build system — install steps are declarative, run by the client.
- Not an identity service — relies on Git host identity.
- Not a payment or license-enforcement system.

## 4. Terminology

The keywords **MUST**, **MUST NOT**, **SHOULD**, **SHOULD NOT**, **MAY** in this document are to be interpreted as described in [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119).

| Term | Definition |
| --- | --- |
| **Tap** | A Git repository conforming to §6. The unit of subscription. |
| **Package** | A single resource described by a manifest file. |
| **Manifest** | A YAML file describing a Package. |
| **Kind** | The type of a Package: `McpServer`, `Skill`, `MiniApp`, or `Registry`. |
| **Index** | A generated `index.json` summarizing all packages in a Tap. |
| **Catalog** | The in-memory union of all subscribed taps, computed by the Client. |
| **Client** | Any software that consumes SORP taps (web site, desktop app, CLI). |
| **Trust level** | A self-declared property of a Tap, gated by the Client (§7). |

## 5. Conformance

A **Conforming Tap** **MUST**:

- Provide `tap.yaml` and `index.json` at the repository root.
- Every entry in `index.json` resolves to a parseable manifest at `manifestPath`.
- Every manifest validates against the JSON Schema for its `kind`.

A **Conforming Client** **MUST**:

- Reject any tap or manifest with an unknown required field.
- Honor the trust rules in §7.
- Honor the conflict resolution rules in §12.
- Display the tap source URL and install steps before any installation.

## 6. Tap Layout

A Tap **MUST** be a Git repository structured as follows on its default branch:

```plaintext
<tap-root>/
├── tap.yaml              # required
├── index.json            # required, generated by CI
├── packages/             # required
│   ├── mcp/<slug>.yaml
│   ├── skill/<slug>.yaml
│   ├── miniapp/<slug>.yaml
│   └── registry/<slug>.yaml
├── LICENSE               # required
└── README.md             # recommended

```

A Tap **MAY** omit kind directories it does not supply. The `supports[]` field in `tap.yaml` is authoritative.

`<slug>` **MUST** match `^[a-z0-9][a-z0-9-]*[a-z0-9]$` and **SHOULD** equal `metadata.name` of the manifest it contains.

## 7. Tap Manifest (`tap.yaml`)

```yaml
apiVersion: sorp.dev/v1
kind: Tap
metadata:
  name: superone-official
  displayName: SuperOne Official
  description: Curated default tap for SuperOne.
  homepage: https://super-one.dev/resources
  maintainers:
    - { name: SuperOne Team, github: WHQ25 }
spec:
  trust: official            # official | community | private
  supports: [McpServer, Skill, MiniApp, Registry]
  schemaVersion: v1          # SORP apiVersion this tap targets
  signing:                   # reserved for v0.2
    enabled: false

```

### 7.1 Trust rules (normative)

- `official` — **MUST NOT** be self-honored. A Client **MUST** treat `official` as authoritative only when the tap repo URL appears in the Client's built-in allowlist maintained by the Client vendor.
- `community` — Vetted via the SORP community process (TBD v0.2); informational at v0.1.
- `private` — Any other tap. Clients **MUST** render with explicit "third-party" UI affordances.

## 8. Package Manifest — common fields

Every Package manifest **MUST** carry:

```yaml
apiVersion: sorp.dev/v1
kind: McpServer | Skill | MiniApp | Registry
metadata:
  name: <slug>                # required, see §6
  version: 0.1.0              # required, SemVer 2.0
  author:
    name: Jane Doe            # required
    url: https://...          # optional
    github: janedoe           # SHOULD be present
  license: MIT                # required, SPDX identifier
  summary: One-line pitch.    # required, <= 120 chars
  description: |              # optional, Markdown
    Multi-paragraph long form.
  tags: [files, storage]      # optional, lowercase kebab
  homepage: https://...       # optional
  repository: https://...     # required for source-based kinds
  screenshots:                # optional
    - { url: ./screenshots/1.png, alt: Main view }
  createdAt: 2026-04-01T00:00:00Z   # optional
  updatedAt: 2026-05-12T00:00:00Z   # optional
spec:
  # kind-specific, see §9

```

`metadata.version` is the Package's own version, independent of SORP's `apiVersion`.

## 9. Kind-specific `spec`

### 9.1 `kind: McpServer`

An MCP server may be distributed in several formats. The `source.type` discriminator selects one and determines which other fields are required and which **MUST NOT** appear.

#### 9.1.1 Source types

| type | Semantics | `install` | `entrypoint` |
| --- | --- | --- | --- |
| `git` | Source repository; the Client builds it locally. | **REQUIRED** | Declared explicitly. |
| `npm` | npm package, executed via `npx`. | **MUST NOT** appear. | Defaults to `npx -y <package>@<version>`; manifest **MAY** override `args` / `env`. |
| `pypi` | PyPI package, executed via `uvx`. | **MUST NOT** appear. | Defaults to `uvx <package>@<version>`; manifest **MAY** override. |
| `docker` | Container image. | **MUST NOT** appear. | Defaults to `docker run --rm -i <image>:<tag>`; manifest **MAY** override. |
| `mcpb` | MCP Bundle ([Anthropic DXT](https://github.com/anthropics/dxt) format); a single-file archive that carries its own `manifest.json`. | **MUST NOT** appear. | **MUST** be derived from the bundle's internal `manifest.json` by the Client. Any `entrypoint` in the SORP manifest is informational and **MUST** be overridden by the bundle. |
| `github-release` | A prebuilt artifact published on a GitHub Release. | **MAY** appear (post-extract scripts). | Declared explicitly. |

#### 9.1.2 Examples

**Git source (build from source):**

```yaml
spec:
  source:
    type: git
    url: https://github.com/modelcontextprotocol/servers
    ref: v0.5.1               # tag/branch/commit; commit RECOMMENDED
    subdir: src/filesystem
  install:
    - { run: "npm install" }
    - { run: "npm run build" }
  entrypoint:
    command: node
    args: ["dist/index.js"]
    env:
      - { name: ALLOWED_DIR, required: true, description: "Root directory the server can access." }
  transport: stdio            # stdio | sse | streamable-http
  compat:
    harness: [claude-code, codex, superone]
    os: [darwin, linux, win32]

```

**npm package:**

```yaml
spec:
  source:
    type: npm
    package: "@modelcontextprotocol/server-filesystem"
    version: "0.5.1"
  entrypoint:
    args: ["--allowed-dir", "${ALLOWED_DIR}"]  # appended after the default npx args
  transport: stdio
  compat:
    harness: [claude-code, codex, superone]

```

**MCP Bundle (**`.mcpb`**):**

```yaml
spec:
  source:
    type: mcpb
    url: https://github.com/acme/cool-mcp/releases/download/v1.2.0/cool-mcp.mcpb
    sha256: "<bundle sha256>"     # RECOMMENDED for integrity
  transport: stdio
  compat:
    harness: [claude-code, codex, superone]
    os: [darwin, linux, win32]

```

When `source.type` is `mcpb`, a Client **MUST**:

1. Download the bundle and, if `sha256` is provided, verify the checksum before extracting.
2. Extract the archive with a **non-streaming** zip reader. Streaming extractors have been observed to silently drop trailing entries in bundles with many files; non-streaming readers (e.g. `unzipper`'s `Open.file()`) are required.
3. Parse the bundle's internal `manifest.json` (DXT schema) to obtain the runtime contract — `command`, `args`, `env`, `permissions`, etc.
4. Treat the SORP manifest as discovery-only metadata: the bundle's `manifest.json` is **authoritative** for any field both files define.

This separation avoids dual maintenance — bundle authors update a single source (the bundle), and the SORP manifest only pins which bundle version the Tap currently advertises.

#### 9.1.3 Common fields (all source types)

```yaml
transport: stdio | sse | streamable-http   # required
compat:
  harness: [claude-code, codex, superone]  # required
  os: [darwin, linux, win32]               # optional; absent means all

```

### 9.2 `kind: Skill`

```yaml
spec:
  source:
    type: git
    url: https://github.com/anthropics/skills
    ref: <commit-sha>
    subdir: data-science/csv-explorer
  entrypoint:
    file: SKILL.md            # path within `subdir`
  triggers:                   # optional, declarative hints
    - "analyze CSV"
    - "csv summary"
  compat:
    harness: [claude-code, codex]

```

Skills are content-only — no install steps. The Client copies `subdir` into the target harness's skills directory.

### 9.3 `kind: MiniApp`

```yaml
spec:
  source:
    type: github-release
    url: https://github.com/acme/cool-miniapp
    artifact: "cool-miniapp-{version}.s1app"
  manifest: miniapp.json      # SuperOne manifest path inside the artifact
  permissions:                # mirrors miniapp.json for discovery
    - clipboard:read
    - net:fetch
  compat:
    harness: [superone]       # MUST be exactly [superone]
    superoneMin: "0.40.0"

```

### 9.4 `kind: Registry`

A meta-resource pointing to another Tap. Used to advertise third-party marketplaces (Anthropic, vendor-specific, company-internal).

```yaml
spec:
  tap:
    type: git                 # git only at v0.1 (see §13)
    url: https://github.com/anthropics/claude-marketplace
    ref: main
  trust: official             # informational; Clients re-evaluate per §7
  supports: [Skill]           # mirrors target's tap.yaml
  publisher:
    name: Anthropic
    url: https://anthropic.com

```

Adding a `Registry` package to a Tap **does not** auto-subscribe consumers; it only makes the Registry discoverable. The user **MUST** explicitly opt in.

## 10. Index (`index.json`)

Generated by Tap CI (e.g. GitHub Action on push to default branch) and committed back. Clients **MUST NOT** synthesize the index from `packages/` locally; they read `index.json` as-is. The index is the wire contract.

```json
{
  "apiVersion": "sorp.dev/v1",
  "kind": "Index",
  "tap": "superone-official",
  "generatedAt": "2026-05-24T10:00:00Z",
  "packages": [
    {
      "kind": "McpServer",
      "name": "filesystem",
      "slug": "anthropic/filesystem",
      "version": "0.5.1",
      "summary": "Access local files via MCP.",
      "tags": ["files"],
      "manifestPath": "packages/mcp/filesystem.yaml",
      "manifestSha": "<sha256-of-manifest-file>",
      "updatedAt": "2026-05-12T00:00:00Z"
    }
  ]
}

```

`manifestSha` lets Clients detect drift without re-parsing every YAML on refresh.

## 11. Naming, Slug, and Versioning

- **Slug** (`metadata.name`) — `^[a-z0-9][a-z0-9-]*[a-z0-9]$`, ≤ 64 chars; **MUST** be unique within `<tap, kind>`.
- **Globally addressable ID** — `<tap>/<kind>/<slug>`, e.g. `superone-official/mcp/filesystem`.
- **Authorship vs slug** — `metadata.author.github` is informational; it does **not** namespace the slug. Taps are the namespace.
- **Version** — SemVer 2.0. Pre-release identifiers permitted (`0.5.1-rc.1`).
- **Source pinning** — Clients **SHOULD** record both `metadata.version` and the resolved commit SHA at install time.

## 12. Resolution and Conflicts

A Client subscribes to an ordered list of Taps. When building the Catalog:

1. Iterate Taps in subscription order.
2. For each `<kind, slug>` already present from a prior Tap, **do not overwrite**. Attach as `alternates[]`.
3. UI **MUST** surface that alternates exist and let the user pick.
4. `featured` flags are per-Tap; the Client **MUST NOT** synthesize cross-Tap featured lists.
5. Clients **MUST NOT** auto-install from a `community` or `private` Tap without explicit user confirmation.

## 13. Tap Transport

v0.1 supports **Git transport only**:

- `git clone --depth 1 <url>` on first subscribe.
- `git pull --ff-only` on refresh.
- Authentication via the system Git credential helper. The Tap manifest **MUST NOT** carry credentials.

HTTP transport (CDN-only `index.json` consumption) is **deferred to v0.2**.

## 14. Security Considerations

- A Tap can declare any `trust` value, but `official` is honored only via the Client's allowlist (§7).
- Clients **MUST** display the Tap source URL on every detail page.
- Clients **SHOULD** verify `manifestSha` from `index.json` matches the actual file at `manifestPath` before installing.
- Install steps (`spec.install[]`) are arbitrary shell — Clients **MUST** show them verbatim before execution and require confirmation.
- Mini-apps additionally declare `permissions[]`; the SuperOne runtime enforces them in its sandbox.
- This spec does **not** define artifact signing in v0.1. The `tap.yaml > spec.signing` field is reserved; semantics TBD in v0.2.

## 15. Spec Versioning

- `apiVersion` is `sorp.dev/v<major>`.
- Minor draft updates within a major are additive only.
- Breaking changes bump major and **MUST** ship a migration note.
- Clients **MUST** reject manifests with an unknown `apiVersion` major.

## 16. Vendor Extensions

Implementations **MAY** add fields under an `x-<vendor>-` prefix (e.g. `x-superone-screenshotsDark`). Unknown `x-*` fields **MUST** be ignored by other Clients. No other unknown fields are permitted at the root of a manifest or under `spec` at v0.1.

## 17. Open Questions (v0.2 Candidates)

- Artifact signing (Sigstore / minisign?).
- HTTP-only Taps (CDN-friendly, no Git client required).
- Localization of `metadata.summary` / `description` (zh-CN, …).
- Deprecation and yank semantics.
- Cross-package dependencies (e.g. a MiniApp depending on a McpServer).
- Privacy-preserving telemetry for "trending" / "install count".
- Governance process for awarding `community` trust.

## Appendix A — Minimal Tap Example

```plaintext
acme-tap/
├── tap.yaml
├── index.json
├── packages/
│   └── mcp/hello-world.yaml
├── LICENSE
└── README.md

```

`tap.yaml`

```yaml
apiVersion: sorp.dev/v1
kind: Tap
metadata:
  name: acme-tap
  displayName: Acme Examples
  description: Demo tap.
  homepage: https://acme.example
  maintainers:
    - { name: Jane, github: jane }
spec:
  trust: community
  supports: [McpServer]
  schemaVersion: v1

```

`packages/mcp/hello-world.yaml`

```yaml
apiVersion: sorp.dev/v1
kind: McpServer
metadata:
  name: hello-world
  version: 0.1.0
  author: { name: Jane, github: jane }
  license: MIT
  summary: Returns "hello, world".
  repository: https://github.com/jane/hello-mcp
spec:
  source:
    type: git
    url: https://github.com/jane/hello-mcp
    ref: v0.1.0
  install:
    - { run: "npm install" }
  entrypoint:
    command: node
    args: ["index.js"]
  transport: stdio
  compat:
    harness: [claude-code, codex, superone]

```
